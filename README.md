# Subtitler

Приложение для следователей: видео с иностранной речью → то же видео с вшитыми
русскими субтитрами, с проверкой и правкой перевода каждой реплики перед
вшиванием.

- **Платформы:** Windows 10/11 (переносимый ZIP, без прав администратора),
  Android 8+ (APK). macOS — стенд для разработки, не для раздачи.
- **Распознавание:** Yandex SpeechKit v1, **перевод:** Yandex Translate v2
  (машинный переводчик, не языковая модель).
- **16 языков** распознавания: русский, английский, турецкий, узбекский,
  казахский, немецкий, французский, испанский, итальянский, португальский
  и бразильский, польский, нидерландский, финский, шведский, иврит.
- **Своего бэкенда нет.** Каждый пользователь вводит собственный API-ключ
  Яндекс Облака; ключ хранится только на его устройстве.

> **Важно.** Звук из видео и распознанный текст уходят на серверы Яндекс
> Облака: там речь распознаётся и переводится. Можно ли передавать туда
> материалы дела, решает регламент вашего ведомства.

## Как пользоваться

1. Распакуйте ZIP целиком и запустите `subtitler.exe`. При первом запуске
   введите API-ключ Яндекс Облака: программа проверит его переводом и
   распознаванием и сохранит.
2. Перетащите видео в окно программы или на значок `subtitler.exe` — или
   нажмите «Выбрать файл». Обработка начнётся сама: язык речи программа
   определит без вопросов. Если программа уже открыта, видео со значка
   уйдёт в её окно. Если там открыт предпросмотр другого видео, идёт
   работа с другим видео или смена ключа, программа попросит сначала
   закончить и перетащить видео ещё раз.
3. В предпросмотре видео играет с субтитрами. Исправьте перевод там, где
   нужно: жёлтые строки стоит проверить. Если перевод бессмысленный —
   «Не тот язык?».
4. «Сохранить видео с субтитрами» — рядом с исходником появится
   `<имя>_ru.mp4`, а субтитры `<имя>_orig.srt` и `<имя>_ru.srt` лежат там с
   конца обработки. Если рядом с видео писать нельзя, файлы сохраняются в
   папку программы, путь виден на плашке.

На Android то же самое через «Выбрать видео», а готовое видео и оба .srt
отдаются кнопкой «Поделиться».

## Как это работает

1. Из видео извлекается звук, паузы в речи ищутся `silencedetect` с
   подбором порога: на шумных записях тихих пауз не бывает, и порог
   опускается по цепочке до −15 dB.
2. По паузам речь режется на реплики по 2–8 секунд и кодируется в OggOpus.
3. Каждая реплика распознаётся отдельным запросом с **явно указанным языком**
   (значения `auto` в API v1 нет).
4. Язык определяется сам, без вопросов. Две самые длинные реплики из разных
   частей ролика распознаются моделями языков из настроек (по умолчанию
   турецкий и узбекский) и сравниваются **по словам**: доля слов своего
   языка, окончания, «чужие» слова соседнего языка. Если отрыв мал — ещё две
   реплики, только двумя лидерами. Обработка идёт дальше в любом случае, а
   при сомнении предпросмотр показывает жёлтую плашку «Скорее всего …» с
   кнопкой «Распознать как …». Язык меняется меню «Не тот язык?»; пробы и
   уже распознанные варианты повторно не оплачиваются.
5. Реплики переводятся на русский, человек правит перевод, и субтитры
   вшиваются в видео. Видео пишется во временный `<имя>_ru.partial.mp4` и
   получает своё имя только после проверки **по картинке**, что субтитры в
   кадре видны: libass без шрифта завершается успешно, но не рисует ничего.

Уже распознанное сохраняется в файл сессии рядом с видео
(`<видео>.subtitler.json`) после каждой реплики: отмена, обрыв сети или
закрытое окно не заставят платить за него второй раз. Подробно —
в [спецификации](docs/superpowers/specs/2026-09-10-subtitler-design.md).

## Сборка

```bash
flutter pub get
flutter test                                # все тесты; нужен ffmpeg (см. ниже)
flutter test integration_test -d windows    # живой плеер предпросмотра
flutter build apk --release                 # Android, ~62 МБ, arm64
flutter build macos --release               # интерфейс следователя на Mac, для разработки
```

Windows собирается только на Windows (нужен MSVC) — этим занимается
`.github/workflows/build.yml`: там же скачивается ffmpeg, проверяется наличие
libass, и всё упаковывается в переносимый ZIP.

**ffmpeg.** На Android он вкомпилирован в приложение, на Windows кладётся
рядом с exe. Тестам и отладке нужен свой — причём **обязательно с libass**,
иначе фильтра `subtitles` нет и вшивание невозможно. На Windows подходит
сборка gyan.dev release-essentials 9.0.1, как в CI:

```powershell
$env:SUBTITLER_FFMPEG = 'C:\…\ffmpeg-9.0.1-essentials_build\bin\ffmpeg.exe'
```

На macOS:

```bash
brew install ffmpeg-full     # формула из homebrew-core, keg-only
export SUBTITLER_FFMPEG="$(brew --prefix ffmpeg-full)/bin/ffmpeg"
export SUBTITLER_FFPROBE="$(brew --prefix ffmpeg-full)/bin/ffprobe"
```

Тесты берут ffmpeg из `SUBTITLER_FFMPEG`, а без неё — из PATH. Если его нет
нигде, тестовые файлы с синтетическими роликами падают при загрузке. С
ffmpeg без libass тесты вшивания честно помечаются пропущенными с
объяснением причины. Живые тесты плеера (`integration_test`) без
`SUBTITLER_FFMPEG` пропускаются молча.

## Отладка

Приложение пишет подробный журнал: каждая команда ffmpeg попадает туда в
виде строки для терминала, вместе с кодом возврата. Журнал дублируется в
файл: на Windows — `%LOCALAPPDATA%\ru.subtitler\subtitler\subtitler.log`
(прошлый запуск — `subtitler.prev.log`), на Android — в папке
приложения. API-ключ регистрируется как секрет и вырезается из любых
записей; текста реплик в журнале нет, а папки с видео (в их названиях
бывают дело и фамилии) заменены на «…», имя файла видео остаётся. Поэтому,
чтобы повторить команду ffmpeg руками, подставьте вместо «…» папку видео.
Скрыты именно папки с видео: пути профиля — папка программы, рабочая
папка, файл журнала, в них имя учётной записи Windows — остаются как
есть. Журнал можно отправить разработчику.

Отладочный стенд — «⋮ → Отладочный стенд»: пункт есть в отладочной сборке
(`flutter run`) или при переменной окружения `SUBTITLER_DEBUG=1`.

## Готовые сборки

**Ссылка для следователей — [релизы](../../releases).** Архив там скачивается
без аккаунта GitHub и не исчезает, а на странице релиза написано, как
запустить программу. Релиз публикуется сам, когда в репозиторий отправлен
тег вида `v0.1.0`:

```bash
git tag v0.1.0
git push origin v0.1.0
```

**Перед тегом — обязательно вручную** на Windows:
`flutter test integration_test -d windows` с заданной `SUBTITLER_FFMPEG`, а
затем запуск `subtitler.exe` из собранного ZIP до предпросмотра с кадром.
CI плеер предпросмотра не запускает: обновление Flutter или media_kit, после
которого предпросмотр падает или показывает чёрный кадр, прошло бы все его
проверки (спецификация, §14).

Сборки для разработчиков собираются в GitHub Actions при каждом пуше в
`main` ([последние сборки](../../actions)). Скачать их может только
вошедший в аккаунт GitHub, и живут они две недели — отправлять такие
ссылки следователям бесполезно:

| Платформа | Что скачивать | Размер |
|---|---|---|
| Windows 10/11 x64 | `subtitler-windows-x64.zip` — распаковать и запустить `subtitler.exe` | ~69 МБ (распакованный — ~178 МБ) |
| Android 8+, arm64 | `app-release.apk` | ~62 МБ |

Устанавливать ничего не нужно: ffmpeg, плеер предпросмотра (libmpv и ANGLE),
шрифт и библиотеки Visual C++ лежат внутри. APK пока подписан отладочным
ключом — перед раздачей нужен свой keystore.

**Для ИТ-службы.** Рядом с `subtitler.exe` лежат неподписанные DLL, в том
числе `libmpv-2.dll`, `libEGL.dll`, `libGLESv2.dll`. Если на ПК действуют
AppLocker или WDAC, папку программы нужно разрешить целиком: без любой из
этих библиотек приложение не запустится.

## Статус

Готово ядро и интерфейс следователя: ввод и проверка ключа, перетаскивание
видео в окно и на значок программы, обработка с автоопределением языка,
предпросмотр с плеером и правкой перевода, смена языка через «Не тот
язык?», сохранение видео с проверкой, что субтитры видны. Android — тот же
поток через «Выбрать видео» и «Поделиться». Тестов в `flutter test` — 783
(прогон 2026-09-25 на Windows: один, про chmod, там пропускается), плюс
живой тест плеера в `integration_test`.

настоящих записях.
