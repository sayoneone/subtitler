# Приёмочные прогоны

Сквозная проверка ядра на настоящих роликах. Сами видеофайлы в репозиторий
не коммитятся (следственные материалы) — разработчик кладёт их локально
в `samples/`.

```bash
export YC_API_KEY='<ключ сервисного аккаунта>'
dart run tool/pipeline_cli.dart test/acceptance/samples/v35.mp4 --lang tr-TR
```

## Эталон (ручной прогон 2026-09-02, все три ролика турецкие)

| Ролик | Длительность | Порог | Сегментов |
|---|---|---|---|
| v52 | 52.00 | −15dB | 9 |
| v26 | 25.71 | −18dB | 5 |
| v35 | 34.80 | −30dB | 6 |

Границы сегментов — в плане
`docs/superpowers/plans/2026-09-11-core-engine.md`, задача 16.
Расхождение больше 0.05 с означает регрессию в сегментаторе, а не повод
править эталон.

Ожидаемое по каждому ролику:

1. Выбранный порог и число сегментов совпали с таблицей.
2. Турецкий текст осмысленный: в v35 должны быть слова про весы (`***`)
   и субботу (`***`).
3. Участки без речи получили статус `empty` и не попали в SRT.
4. Последняя строка вывода — `Готово: ... (субтитры в кадре видны)`.
5. Открыть `_ru.mp4` и глазами убедиться, что русский текст читается
   и не выходит за кадр.

## Про вшивание на macOS

`ffmpeg` из homebrew-core собран **без libass** (проверить:
`ffmpeg -filters | grep subtitles` — пусто), поэтому фильтра `subtitles`
в нём нет и шаг вшивания на такой машине не выполняется: CLI честно
сообщает об этом и завершается с кодом 3, успев записать оба `.srt`.

Системный ffmpeg менять не нужно. В homebrew-core есть параллельная
формула `ffmpeg-full` — та же версия, но с libass; она keg-only, то есть
не подменяет уже установленный ffmpeg и ни с чем не конфликтует:

```bash
brew install ffmpeg-full
export SUBTITLER_FFMPEG="$(brew --prefix ffmpeg-full)/bin/ffmpeg"
export SUBTITLER_FFPROBE="$(brew --prefix ffmpeg-full)/bin/ffprobe"
flutter test                                # пропущенные тесты вшивания оживут
dart run tool/pipeline_cli.dart samples/v35.mp4 --lang tr-TR
```

Проверено 2026-09-11: с `ffmpeg-full` весь набор проходит целиком
(90 тестов, ни одного пропущенного), с системным ffmpeg — 86 и 4
пропущенных. Опции вида `--with-libass` у Homebrew давно убраны,
а в кране `homebrew-ffmpeg` такого флага и не было: libass там
подключается безусловно.

В релизных сборках libass есть всегда: на Windows — gyan.dev
release-essentials, на Android — ffmpeg_kit_flutter_new full-gpl,
поэтому на продукт отсутствие libass у разработчика не влияет.
