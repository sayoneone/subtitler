# Subtitler — спецификация (дизайн-документ)

Дата: 2026-09-10 · Статус: черновик на вычитке · Авторы: Саят + Claude

Приложение для следователей: загрузил видео с речью на турецком или узбекском —
получил то же видео с вшитыми русскими субтитрами, с возможностью проверить и
поправить каждую реплику до вшивания.

---

## 1. Цель и пользователи

Пользователь — следователь без технической подготовки, на служебном ПК
(Windows, часто без прав администратора) или служебном/личном Android-телефоне.
Видео — короткие ролики (типично WhatsApp, 30–90 с, 848×480), звук с шумом
работающей техники. Пользователь вводит **свой** API-ключ Яндекс Облака один
раз при первом запуске.

Критерий успеха: от «перетащил файл» до «получил готовый ролик» — без чтения
инструкций; на каждом этапе видно, что происходит; сомнительные места
распознавания явно подсвечены, а не молча пропущены или выдуманы.

## 2. Не-цели

- **Никакого своего бэкенда**: ни сервера, ни сбора ключей, ни телеметрии,
  ни аккаунтов. Приложение общается только с API Яндекс Облака напрямую.
- iOS (распространение вне App Store — отдельная бюрократия; не в этой версии).
- Полноценный субтитровый редактор общего назначения (стили, караоке, ASS).
- Длинные видео: пайплайн рассчитан на ролики **до 15 минут** (поведение при
  большей длительности — §5).
- Автоматический выбор языка «молча»: язык всегда подтверждает человек.

## 3. Платформы и дистрибуция

| | Windows 10/11 x64 | Android 8+ |
|---|---|---|
| Формат | portable ZIP: распаковал → запустил, без установки и прав админа | APK напрямую (без магазинов) |
| ffmpeg | `ffmpeg.exe` в папке приложения | библиотека, слинкованная в приложение |
| Ключ | Credential Manager | Keystore |
| Приём видео | drag-and-drop на окно, диалог выбора | «Поделиться» из WhatsApp/галереи + выбор файла |
| Выдача | файлы рядом с исходником | видео в галерею + «Поделиться» (видео и оба .srt одним интентом) |

Одна кодовая база Flutter. macOS-таргет собирается только для разработки.

**Android, приём файла:** видео, полученное **любым** из двух путей (share-интент
или `file_selector`), приходит как `content://`-URI и **обязательно копируется**
в папку приложения перед передачей в ffmpeg — библиотека не читает SAF-URI напрямую.

## 4. Первый запуск и ключ

Экран онбординга (показывается, пока ключ не сохранён):

1. Короткий текст: какой ключ нужен (статический API-ключ сервисного аккаунта
   Яндекс Облака) и какие роли у него должны быть: `ai.speechkit-stt.user` и
   `ai.translate.user`. Кнопка-ссылка «Как создать ключ» — открывает инструкцию.
2. Поле ввода с маскировкой (`AQVN…`), кнопка «Проверить и сохранить».
3. Проверка двумя микро-запросами, каждый со своим индикатором:
   - Перевод: `translate/v2/translate`, одно слово → ✅/❌ роль перевода;
   - Распознавание: `stt:recognize` с бандленным аудио ~0.5 с (важен только
     HTTP-статус, не текст) → ✅/❌ роль распознавания.
4. Обе галочки зелёные → ключ уходит в защищённое хранилище ОС и нигде больше
   не появляется (ни в логах, ни в файлах сессий). Ключ можно сменить в настройках.

Ошибки проверки переводятся на человеческий: «ключ неверный или отозван» (401),
«у сервисного аккаунта нет роли … — добавьте её в консоли облака» (403),
«нет доступа к интернету».

**Отказ чтения хранилища** (переустановка ОС, сброс Keystore, другой профиль
Windows) трактуется как «ключа нет» → снова экран онбординга. Приложение
никогда не падает из-за нечитаемого хранилища.

## 5. Основной сценарий

```
Главный экран ──видео──▶ [проверка длительности] ──▶ Язык ──▶ Обработка ──▶ Редактор ──▶ Экспорт
      ▲                        >15 мин: предупреждение,   │        │  (кнопка «Отмена»)      │
      │                        продолжение на свой риск   │        ▼                         ▼
      └──────────── «Отмена» ──────────────────────────────┘   частичный результат    <имя>_ru.mp4
                                                                  в редакторе          + оба .srt
```

**Проверка длительности** — сразу после выбора файла на главном экране.
Больше 15 минут: мягкое предупреждение («Ролик длиннее 15 минут: обработка
займёт много времени и обойдётся дороже. Продолжить?») с кнопками «Продолжить»
и «Отмена». Это не жёсткий стоп — следователь решает сам.

**Экран выбора языка**: кнопки «Турецкий (tr-TR)», «Узбекский (uz-UZ)» и
«Определить». «Определить» распознаёт до двух самых длинных сегментов **обеими**
моделями и показывает экран сравнения: два столбца текста (турецкий вариант /
узбекский вариант) и кнопки «Это турецкий» / «Это узбекский».
**Предвыбора «лучшего» варианта нет** — решает человек, глядя на оба текста
(алгоритмическое ранжирование давало бы ложную уверенность в единственном месте,
где эта уверенность опасна). Вырожденные случаи: найден один сегмент — пробуется
он один; сегментов нет вовсе — кнопка «Определить» недоступна, язык выбирается
вручную.

**Отмена обработки**: на экране «Обработка» всегда доступна кнопка «Отмена».
По ней прерываются активные HTTP-запросы (`CancelToken`) и процесс ffmpeg,
уже полученные результаты сохраняются в сессию (§9), временные файлы удаляются,
и приложение предлагает выбор: «Открыть, что успели» (редактор с частичным
результатом) или «На главный экран». Повторный запуск продолжит с того же места
и не оплатит заново уже распознанные сегменты.

**Смена языка после обработки**: в редакторе есть кнопка «Распознать заново на
другом языке» — на случай, когда язык выбран ошибочно и текст вышел
бессмысленным. Предупреждает, что распознавание будет оплачено повторно, и
сохраняет ручные правки в резервной копии сессии.

## 6. Пайплайн обработки

Портируется с проверенного вручную прогона (2026-09-02, три реальных ролика);
все числа — оттуда.

1. **Аудио**: `ffmpeg -i video -vn -ac 1 -ar 48000 -c:a pcm_s16le audio.wav`.
2. **Паузы, адаптивный порог**: `silencedetect` последовательно на
   −30 dB/0.3 с → −25/0.3 → −20/0.25 → −18/0.25 → −15/0.25, пока не найдётся
   ≥ 1 паузы на 15 с длительности (шумные ролики со стройплощадок не имеют пауз
   на −30 dB — проверено). Найденный порог пишется в сессию.
   **Терминальный фолбэк**: если пауз не нашлось ни на одном пороге, ролик
   режется принудительно по 7.2 с без опоры на паузы; в сессии ставится флаг
   `forced_split`, а в редакторе показывается плашка «Паузы в речи не найдены,
   ролик разрезан механически — проверьте границы реплик».
3. **Сегменты**: речевые интервалы между паузами; склейка соседних, если зазор
   ≤ 1.0 с и суммарно ≤ 8 с; интервалы > 8.5 с делятся по микропаузам
   (порог +3 dB, d = 0.15 с), в крайнем случае принудительно по ~7.2 с;
   паддинг в тишину — `min(0.12 с, зазор_до_соседа / 2)` с каждой стороны,
   чтобы соседние сегменты **никогда не перекрывались** (иначе один и тот же
   звук ушёл бы в платный API дважды и дал бы наложение реплик в SRT);
   точность границ 0.01 с. Целевая длина 2–8 с (лимит STT v1 — 30 с / 1 МБ).
   **Ноль сегментов** (звук есть, речи нет): пайплайн останавливается с
   сообщением «Речь в ролике не обнаружена», редактор открывается пустым —
   реплики можно добавить и заполнить вручную.
4. **Кодирование**: каждый сегмент → OggOpus 64k mono (`-c:a libopus -b:a 64k`).
5. **Распознавание**: POST
   `stt.api.cloud.yandex.net/speech/v1/stt:recognize?topic=general&format=oggopus&lang=<код>`,
   заголовок `Authorization: Api-Key …`, тело — ogg.
   `format=oggopus` передаётся **явно** (в ручном прогоне он же и является
   значением по умолчанию, но полагаться на умолчание API не нужно);
   `sampleRateHertz` для OggOpus не передаётся. `folderId` **не передаётся** —
   доки прямо запрещают его для ключа сервисного аккаунта: каталог берётся из
   самого аккаунта. Язык всегда явный, полные коды `tr-TR`/`uz-UZ`; узбекский
   возвращается латиницей — показываем как есть.
   Параллельно ≤ 4 запросов (квота API — 20 rps).
6. **Перевод**: машинный (нейросетевой переводчик Яндекса, Translate API v2 —
   не языковая модель: он дешевле, детерминирован и не требует промптов).
   Непустые реплики уходят батчами в `translate/v2/translate`,
   `folderId` так же не передаётся (то же правило сервисного аккаунта).
   Коды языков здесь — **короткие**: `targetLanguageCode: "ru"`,
   `sourceLanguageCode` — `"tr"` или `"uz"`, полученные преобразованием кода
   распознавания (`tr-TR` → `tr`, `uz-UZ` → `uz`). Передача полного кода
   локали в Translate — ошибка запроса. Лимит 10 000 знаков на запрос
   считается по **сумме** всех строк батча; квота — 20 запросов в секунду
   и 1 млн знаков в час (нам с батчами до неё далеко).

   **Про узбекский отдельно.** В переводчике это два разных языка: `uz` —
   латиница, `uzbcyr` — кириллица. Мы отправляем `uz`, потому что
   распознавание узбекского в SpeechKit возвращает именно латиницу (так
   написано в документации и так вышло на живом прогоне). Если следователь
   вручную перепишет реплику кириллицей и попросит перевести заново, для неё
   нужен код `uzbcyr` — определять по фактическому алфавиту текста, а не по
   выбранному языку ролика.
7. **Итог этапа**: список реплик → редактор.

**Статус каждой реплики** (поле в модели и в файле сессии) — от него зависит,
что будет отправлено в платный API при возобновлении:

| Статус | Значение | При возобновлении |
|---|---|---|
| `pending` | ещё не распознавалась | отправляется |
| `ok` | распознан непустой текст | не отправляется |
| `empty` | распознано, речи нет (шум техники) | не отправляется |
| `failed` | ретраи исчерпаны или прогон прерван | отправляется |

Реплика со статусом `empty` не попадает в субтитры, но остаётся в таблице серой
строкой: человек видит, что участок не потерян, а осознанно пуст, и может
вписать текст руками.

**Политика ошибок сети — одна и та же для распознавания и перевода**:
429/5xx/сетевые — попытка и до трёх повторов с паузами 1 с, 4 с и 10 с
(итого не больше четырёх обращений и 15 с ожидания на реплику); после
исчерпания реплика получает статус `failed`, **остальной ролик обрабатывается
дальше** и доходит до редактора (терять уже оплаченные соседние сегменты
нельзя). 401/403 — немедленная остановка всего прогона с сообщением про ключ
или роль.

Стоимость (ориентир, тарифы РФ на сентябрь 2026, в приложение не зашивать):
STT тарифицируется на каждый запрос блоками по 15 с с округлением ВВЕРХ
(0.1626 ₽ за блок), перевод — 500.4 ₽ за 1 млн знаков; ролик на 90 с обходится
примерно в 3 ₽. Следствие для сегментации: без необходимости не плодить
сегменты короче ~2 с — каждый всё равно оплачивается как 15 с.

**Прогресс** показывается подписью текущего этапа, а не только числом:
«Извлекаем звук…», «Ищем паузы в речи…» (этап может занять до пяти проходов по
файлу), «Распознаём реплику 4 из 13…», «Переводим…», «Вшиваем субтитры… 47 %».

## 7. Редактор

- **Плеер** (media_kit) проигрывает исходное видео. Субтитры в предпросмотре
  рисует **сам Flutter** виджетом поверх кадра — тем же стилем, что будет вшит
  (белый, чёрная обводка, низ по центру). Правка текста видна в кадре мгновенно,
  без пересборки SRT. Предпросмотр приблизителен: итоговый кадр рисует libass,
  и совпадение с ним не пиксельное.
- **Таблица реплик**: №, тайминги (правятся), оригинал, перевод (правится),
  статус. Клик по строке — перемотка видео на начало реплики. Операции:
  правка текста/таймингов, удаление реплики, склейка соседних, добавление
  пустой реплики на выбранном участке. Разделение реплики — не в v1.
- **Валидация таймингов** при правке: конец не может быть раньше или равен
  началу (ввод отклоняется с подсказкой); пересечение с соседней репликой
  показывается предупреждением в строке и не даёт экспортировать, пока не
  исправлено — иначе на выходе получится некорректный SRT.
- **Подсветка «проверить»** (наследник ручной пометки `[ПРОВЕРИТЬ]`), жёлтым:
  - зацикленный повтор токена ≥ 4 раз подряд (реальный случай: «***» ×8);
  - реплика со статусом `failed` (распознавание не удалось);
  - перевод не получен при непустом оригинале.
  Жёлтая строка не блокирует вшивание — это подсказка, решает человек.
- Счётчик в шапке: «реплик: N, на проверку: M».
- Кнопки: «Вшить субтитры», «Распознать заново на другом языке» (§5).

## 8. Вшивание

- Windows:
  `ffmpeg -i in.mp4 -vf "subtitles=subs.srt:fontsdir=fonts:force_style='FontName=Noto Sans,Outline=2'" -c:v libx264 -crf 18 -preset veryfast -c:a copy out.mp4`
  Кодек и качество заданы явно. Аудио копируется без перекодирования. Шрифт —
  из бандленной папки `fonts/`, чтобы не зависеть от набора шрифтов служебного
  ПК (libass на Windows ищет шрифты через DirectWrite).
- Android: та же команда через ffmpeg_kit_flutter_new, плюс обязательная
  подготовка шрифта: NotoSans-Regular.ttf копируется из ассетов в папку
  приложения и регистрируется через `FFmpegKitConfig.setFontDirectoryList()`,
  а в фильтре дублируется `fontsdir=`. `FontName` — внутреннее имя семейства
  («Noto Sans»), не имя файла.
- **Автопроверка видимости субтитров** (критично: на Android без регистрации
  fontconfig libass «успешно» вшивает невидимый текст с кодом возврата 0).
  Метрика конкретная, устойчивая к шуму компрессии: из середины первой непустой
  реплики берутся кадры исходного и готового видео; в нижней полосе кадра
  (нижние 20 % высоты) считается число «почти белых» пикселей (яркость > 200).
  Вшивание считается успешным, если их прирост ≥ 300 пикселей. Иначе —
  ошибка «Субтитры не отрисовались» (§10), файл-результат не выдаётся как
  готовый.
- Прогресс кодирования: на Windows — парсинг `-progress pipe:1` из stdout
  процесса; на Android — нативный statistics-callback ffmpeg_kit (у библиотеки
  нет доступного из Dart stdout). Это два разных механизма за одним интерфейсом
  `FfmpegRunner`.
- Пути и опции внутри `-vf` собираются хелпером с экранированием `:` `'` `\`
  (на Windows — отдельно двоеточие буквы диска).
- **Имена и коллизии**: `<имя>_ru.mp4`, `<имя>_orig.srt`, `<имя>_ru.srt`.
  Файлы принадлежат этому видео и этой сессии, поэтому перезаписываются без
  вопросов; исключение — если файл занят другим приложением: тогда сообщение
  «Файл <имя> открыт в другой программе, закройте его и повторите».
- **Выдача на Android**: видео сохраняется в галерею (`gal`), а кнопка
  «Поделиться» отправляет одним интентом три файла — mp4 и оба .srt
  (в галерею .srt сохранить нельзя, и без этого они остались бы недоступны).

## 9. Сессия

Рядом с исходником — `<имя>.subtitler.json`: версия схемы, язык, порог тишины,
флаг `forced_split`, реплики со статусами и правками, состояние этапов.

- **Отпечаток исходника** (размер в байтах + длительность до 0.01 с) пишется в
  сессию и сверяется при открытии. Не совпал — сессия считается чужой и
  игнорируется, пайплайн запускается заново. Без этой проверки другой файл с тем
  же именем (обычное дело при работе с копиями вещдоков) молча получил бы чужие
  реплики.
- **Инкрементальная запись**: сессия сохраняется после каждого обработанного
  сегмента и каждого батча перевода, а не в конце. Обрыв сети или падение на
  последней минуте длинного ролика не должны обнулять уже оплаченные вызовы.
- **Папка только на чтение** (вещдоки на защищённом от записи носителе, сетевая
  шара): при неудаче записи рядом с исходником сессия и выходные файлы уходят в
  папку приложения, о чём пользователю показывается плашка с фактическим путём
  и кнопкой «Открыть папку». Гарантия «без повторной оплаты» не должна молча
  ломаться из-за прав на папку.
- Ключ в сессию не пишется никогда. На Android сессии и копии видео всегда
  живут в папке приложения.

## 10. Ошибки

Принцип: каждая ошибка — человеческим языком + что сделать. Карта:

| Ситуация | Сообщение |
|---|---|
| 401 | «Ключ неверный или отозван. Проверьте ключ в настройках» |
| 403 STT / 403 Translate | «У ключа нет роли ai.speechkit-stt.user / ai.translate.user — добавьте в консоли облака» |
| 429 / 5xx | автоповтор молча; после 3 неудач реплика помечается `failed`, обработка продолжается |
| Нет сети | «Нет доступа к интернету. Обработка возможна только онлайн» |
| Файл без аудиодорожки | «В этом видео нет звука» |
| Речи не найдено (0 сегментов) | «Речь в ролике не обнаружена» + пустой редактор для ручного ввода |
| Пауз не найдено ни на одном пороге | ролик режется механически, плашка в редакторе (§6.2) |
| Субтитры не отрисовались (провал автопроверки) | «Субтитры не отрисовались — сообщите разработчику» + «Показать технические детали» |
| Выходной файл занят | «Файл <имя> открыт в другой программе, закройте его и повторите» |
| Нет места на диске | «Недостаточно места на диске для обработки» |
| ffmpeg упал | «Не удалось обработать видео» + кнопка «Показать технические детали» |

Технический лог сессии (без ключа!) — в файл в папке приложения, кнопка
«Открыть лог» в настройках: следователь сможет прислать его нам при проблеме.

## 11. Безопасность и приватность

- Ключ: только в Credential Manager / Keystore; в UI маскирован; в логи,
  сессии и краш-репорты не попадает (краш-репортов внешних нет вообще).
- Данные: аудиосегменты и тексты уходят **только** в API Яндекс Облака по HTTPS.
  Приложение ничего не отправляет никому другому (проверяемо: других доменов
  в коде нет). Допустимость передачи материалов в облако — на стороне
  регламента ведомства; в README будет явное предупреждение.
- Временные файлы (wav, сегменты) удаляются после обработки и при отмене.

## 12. Технологии и зависимости

Версии подтверждены веб-исследованием 2026-09-10 (критичные выборы прошли
адверсариальную перепроверку по живым pub.dev/GitHub/докам). При реализации —
пиновать точно.

- **Flutter stable ≥ 3.44** (на машине разработчика на 2026-09-10 — 3.44.6;
  актуальная stable ветки — 3.47.x). Нижняя граница задана пакетом
  receive_sharing_intent 1.9.0 (требует ≥ 3.38). Версию зафиксировать в CI и
  обновлять только как проверяемую миграцию (см. media_kit ниже).
  Windows-тулчейн: только VS 2022 C++ (VS 2026 Flutter'ом не поддерживается).
  Impeller теперь рендерер по умолчанию на Windows — проверить на старых
  GPU/RDP служебных ПК (есть флаг отключения).
- **ffmpeg**:
  - Windows: статическая сборка gyan.dev **release-essentials 9.0.1**
    (`ffmpeg.exe` ~35–40 МБ): внутри всё нужное — silencedetect, libopus,
    libass (+freetype/fribidi/harfbuzz), libx264. Бинарь зеркалируется в наше
    хранилище артефактов (воспроизводимость сборок).
  - Android: **ffmpeg_kit_flutter_new ^4.6.2** — живой форк закрытого в 2025
    FFmpegKit (релизы еженедельно, июль 2026); базовый пакет = full-gpl,
    FFmpeg 8.1.2, наличие libass/libx264 и фильтра `subtitles` проверено
    внутри самого Maven-артефакта. minSdk 24, 16KB-страницы поддержаны.
    APK собираем только arm64-v8a (~42 МБ установки; armeabi-v7a добавлять
    только если парк старых телефонов потребует — это ещё ~78 МБ).
    Версию пиновать точно и AAR зеркалировать в своё хранилище (форк
    одного мейнтейнера; экосистема ffmpeg-kit уже дважды переживала смену
    рук). Плагин с v4.2.0 умеет и Windows, но на десктопе мы сознательно
    остаёмся на видимом `ffmpeg.exe`: пиновая, проверяемая ИТ-отделом
    сборка вместо скачиваемого на этапе билда бинаря.
    Лицензия итоговой сборки — GPLv3 (из-за libx264): для внутреннего
    использования обязательств нет; при передаче другим ведомствам —
    приложить LICENSE и ссылки на исходники.
- **Плеер**: media_kit ^1.2.6 + media_kit_video ^2.0.1 + media_kit_libs_video
  ^1.0.7. Проект в официальном режиме «limited maintenance» (объявлено
  2025-11-25), но жив. Известный краш hot-restart на Flutter 3.38+ починен в
  git main (PR #1416, май 2026), релиза на pub.dev с фиксом нет → пиновать
  зависимость git-коммитом main (заодно фиксы утечек авг-2026), либо жить с
  полным рестартом при разработке. Обновление Flutter — только как проверяемая
  миграция. +30–40 МБ бинарей (libmpv) на платформу.
- **Ключ**: flutter_secure_storage ^11.1.0. Windows: гибрид «.secure-файлы в
  app-support + ключ-обёртка в Credential Manager» (сборке нужен C++ ATL в VS
  Build Tools). Android: Keystore, minSdk 24; файл хранилища исключить из
  Android Auto Backup (известный «Failed to unwrap key» после восстановления).
  Любая ошибка чтения/расшифровки трактуется как «ключа нет» → снова экран
  онбординга. Хранение per-user — плюс для общих служебных ПК.
- **Share/файлы**: receive_sharing_intent ^1.9.0 (приём SEND-интента; требует
  Flutter 3.38+/AGP 9.2.1/Kotlin 2.4/compileSdk 37 — фиксируем такой тулчейн
  проекта), share_plus ^13.3.0 (актуальный API `SharePlus.instance.share`,
  умеет несколько файлов сразу; прямого deep-link в WhatsApp не бывает —
  системный share sheet), gal ^2.3.3 (галерея; для API ≤29 объявить
  WRITE_EXTERNAL_STORAGE с maxSdkVersion=29), desktop_drop ^0.8.4 (код-путь
  только для Windows), file_selector ^1.1.0 (first-party).
- **Прочее**: dio ^5.11.1 (таймауты, интерсептор Api-Key, CancelToken для
  отмены §5), path_provider ^2.1.6, window_manager ^0.5.2, package_info_plus
  ^10.2.1, wakelock_plus ^1.8.0 (телефон не засыпает при обработке).
  Состояние: ChangeNotifier/ValueNotifier, без фреймворков. UI по-русски:
  строки в одном классе AppStrings + flutter_localizations с locale «ru»
  (иначе системные диалоги Material останутся английскими).
- **Шрифт**: NotoSans-Regular.ttf (кириллица + турецкие символы) в ассетах —
  один и тот же для предпросмотра и вшивания (§8).

## 13. Структура кода

```
lib/
  core/
    models.dart        // Cue{start,end,orig,ru,status,flags}, Session, enums
    pipeline/          // silence_parser, segmenter (чистый Dart, без I/O)
    ffmpeg/            // FfmpegRunner (интерфейс: выполнить + прогресс) →
                       //   ProcessRunner (Windows, -progress pipe:1),
                       //   LibRunner (Android, statistics-callback);
                       //   сборка и экранирование команд — общие
    cloud/             // SpeechKitClient, TranslateClient, ApiKeyValidator,
                       //   RetryPolicy (общая для обоих клиентов)
    srt.dart           // генерация/парсинг SRT
    session_store.dart // <имя>.subtitler.json + отпечаток + фолбэк-путь
  ui/
    onboarding/  home/  language/  processing/  editor/  export/  settings/
  app.dart
```

`core/pipeline`, `srt.dart` и валидация таймингов — чистые функции без I/O:
юнит-тестируются на golden-данных реального прогона. Вся платформенная
специфика заперта в `ffmpeg/` и в приёме/выдаче файлов.

## 14. Сборка и CI

- GitHub Actions, два джоба по тегу релиза:
  - **windows** (VS 2022 toolchain): `flutter build windows --release` → ZIP:
    содержимое `Release/` + рядом с exe ровно три DLL MSVC-рантайма
    (`msvcp140.dll`, `vcruntime140.dll`, `vcruntime140_1.dll` — официальный
    «application-local deployment», работает без прав админа: UCRT входит в
    Windows 10/11) + `tools/ffmpeg/ffmpeg.exe` (gyan release-essentials 9.0.1)
    с его LICENSE + `fonts/NotoSans-Regular.ttf`. Обязательный smoke-тест ZIP
    на чистой VM без VC++ Redistributable — media_kit может дополнительно
    попросить msvcp140_1/_2 или concrt140, добавить по результату теста.
  - **android**: `flutter build apk --release` (arm64-v8a), подпись собственным
    keystore из секретов репозитория.
- Замечания для ИТ (кладутся в README дистрибутива): скачанный из сети ZIP несёт
  Mark-of-the-Web → SmartScreen предупредит при первом запуске (раздавать через
  внутренний файлообменник или «Разблокировать» в свойствах файла); AppLocker/WDAC
  могут блокировать неподписанные exe из пользовательских папок — при жёсткой
  политике нужна подпись кода или white-list от ИТ-отдела.
- Приёмочный прогон перед раздачей: три реальных ролика из ручного прогона
  2026-09-02 на настоящей Windows-машине.

## 15. Тестирование

- Юнит: парсер silencedetect, сегментация (склейка/деление/паддинг без
  перекрытий/терминальный фолбэк), SRT генерация/парсинг, валидация таймингов,
  эвристики подсветки, преобразование кодов языков — golden-данные из реального
  прогона 2026-09-02.
- Клиенты API: фейковый HTTP-сервер (401/403/429/5xx, тексты, батчи перевода),
  проверка возобновления по статусам реплик без повторных вызовов.
- Виджет-тесты: онбординг (обе галочки/ошибки ролей), таблица редактора,
  экран сравнения языков.
- Приёмка: 3 реальных ролика от «файл» до «_ru.mp4», сверка с эталонными SRT;
  на Android дополнительно — тест автопроверки видимости субтитров (специально
  сломанная регистрация шрифта должна давать ошибку, а не «успех»).

## 17. Границы v1 → потом

v1: всё описанное выше. Потом (не сейчас): разделение реплики в редакторе,
пакетная обработка нескольких видео, история обработанных файлов, авто-подбор
громкости для тихой речи (boost-ретрай из ручного прогона), транслитерация
узбекской латиницы в кириллицу, iOS.

Отдельно стоит держать в уме **глоссарий переводчика** (`glossaryConfig`):
Translate v2 позволяет приложить к запросу до 50 пар «термин → перевод»
(пары tr-ru и uz-ru поддерживаются). Для устойчивого перевода профессиональной
лексики и имён это самый дешёвый рычаг, но в v1 он не нужен: сначала надо
увидеть на реальных делах, какие термины переводятся не так.
