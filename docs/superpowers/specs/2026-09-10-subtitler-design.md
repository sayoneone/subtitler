# Subtitler — спецификация (дизайн-документ)

Дата: 2026-09-10, сверена с программой 2026-09-25 · Статус: описывает
сделанное; чего нет — сказано явно · Авторы: Саят + Claude

Приложение для следователей: загрузил видео с иностранной речью (обычно
турецкой или узбекской) — получил то же видео с вшитыми русскими субтитрами,
с возможностью проверить и поправить перевод каждой реплики до вшивания.

---

## 1. Цель и пользователи

Пользователь — следователь без технической подготовки, на служебном ПК
(Windows, часто без прав администратора) или служебном/личном Android-телефоне.
Видео — короткие ролики (типично WhatsApp, 30–90 с, 848×480), звук с шумом
работающей техники. Пользователь вводит **свой** API-ключ Яндекс Облака один
раз при первом запуске.

Критерий успеха: от «перетащил файл» до «получил готовый ролик» — без чтения
инструкций; на каждом этапе видно, что происходит; сомнительные места
распознавания явно подсвечены, а не молча пропущены или выдуманы.

## 2. Не-цели

- **Никакого своего бэкенда**: ни сервера, ни сбора ключей, ни телеметрии,
  ни аккаунтов. Приложение общается только с API Яндекс Облака напрямую.
- iOS (распространение вне App Store — отдельная бюрократия; не в этой версии).
- Полноценный субтитровый редактор общего назначения (стили, караоке, ASS,
  правка времени, склейка реплик — §7).
- Длинные видео: пайплайн рассчитан на ролики **до 15 минут** (поведение при
  большей длительности — §5).
- Вопрос «на каком языке ролик?» до обработки. Язык выбирается автоматически
  всегда, но сомнение не прячется: при неуверенном выборе предпросмотр
  показывает жёлтую плашку со вторым языком, а меню «Не тот язык?» доступно
  всегда (§5).

## 3. Платформы и дистрибуция

| | Windows 10/11 x64 | Android 8+ |
|---|---|---|
| Формат | portable ZIP: распаковал → запустил, без установки и прав админа | APK напрямую (без магазинов); пока подписан отладочным ключом |
| ffmpeg | `tools/ffmpeg/ffmpeg.exe` рядом с `subtitler.exe` | библиотека, слинкованная в приложение |
| Ключ | Credential Manager | Keystore |
| Приём видео | перетаскивание в окно или на значок `subtitler.exe`, «Выбрать файл» | «Выбрать видео» (системный диалог) |
| Выдача | файлы рядом с исходником | «Поделиться»: видео и оба .srt одним интентом |

Одна кодовая база Flutter. macOS-таргет собирается только для разработки.

**Android, приём файла:** видео выбирается системным диалогом
(`file_selector`). Плагин копирует ролик в кеш приложения
(`getCacheDir()/<uuid>/`, file_selector_android 0.5.2+10, `FileUtils.java`)
и отдаёт путь к копии — её и читает ffmpeg. Приём из WhatsApp через
«Поделиться» (share-интент) не подключён: пакет в pubspec есть, но не
используется, фильтра SEND в манифесте нет.

## 4. Первый запуск и ключ

Экран ключа (показывается, пока ключ не сохранён):

1. Короткий текст: какой ключ нужен (API-ключ сервисного аккаунта
   Яндекс Облака) и какие роли у него должны быть: `ai.speechkit-stt.user` и
   `ai.translate.user`. Раскрывающийся блок «Как создать ключ» — пошаговая
   инструкция для консоли облака.
2. Поле ввода с маскировкой (`AQVN…`), кнопка «Проверить и сохранить».
3. Проверка двумя микрозапросами, каждый со своим индикатором:
   - Перевод: `translate/v2/translate`, одно слово → роль перевода;
   - Распознавание: `stt:recognize` с полусекундой тишины в OggOpus,
     вшитой в программу (важен только HTTP-статус, не текст) → роль
     распознавания.
4. Обе проверки прошли → ключ уходит в защищённое хранилище ОС и нигде
   больше не появляется (ни в журнале, ни в файлах сессий). Не прошли —
   прежний ключ (если его меняли) продолжает работать. В настройках ключ
   можно заменить или удалить; пока идёт работа — нельзя.

Ошибки проверки переводятся на человеческий: «Ключ неверный или отозван»
(401), «У ключа нет роли ai.translate.user» / «…ai.speechkit-stt.user»
(403), «Нет доступа к интернету».

**Отказ чтения хранилища** (переустановка ОС, сброс Keystore, другой профиль
Windows) трактуется как «ключа нет» → снова экран ключа. Приложение
никогда не падает из-за нечитаемого хранилища. Если хранилище не прошло
самопроверку при запуске, ключ работает до закрытия программы, и экран
честно об этом предупреждает.

## 5. Основной сценарий

```
Главный экран, предпросмотр, итог отмены или ошибки
   │  видео: перетаскивание в окно, «Выбрать файл»
   │  (файл на значке subtitler.exe — ниже, «Запуск с видео»)
   ▼
[папка? не видео? нет звука?] ── да ──▶ короткое сообщение, экран прежний
   ▼
[> 15 мин и нет готовой сессии] ── «Продолжить?» ── «Отмена» ──▶ экран прежний
   ▼
Обработка: Готовим звук → Определяем язык → Распознаём речь: N из M → Переводим на русский
   │  «Отмена» на любом шаге ──▶ «Обработка остановлена»: «Открыть, что успели» / «На главный экран»
   │  ошибка ──▶ экран ошибки: кнопка по смыслу (§10) и «На главный экран»
   ▼
Предпросмотр: плеер, правка перевода, «Не тот язык?»
   ▼  «Сохранить видео с субтитрами»
<имя>_ru.mp4 рядом с исходником (оба .srt лежат там с конца обработки)
```

**Приём видео.** Видео принимается на главном экране, в предпросмотре и на
экранах «Обработка остановлена» и ошибки — когда программа ничем не занята.
Во время обработки, сохранения и смены языка приём выключен: иначе результат
одного ролика записался бы под именем другого. Папка вместо файла, не видео
(документ, звук без картинки, повреждённый файл) или видео без звуковой
дорожки дают короткое сообщение, этап не меняется.

**Запуск с видео.** Видео, брошенное на значок или ярлык `subtitler.exe`
(или «Открыть с помощью»), приходит аргументом запуска и открывается само
на главном экране, как только программа готова: сразу после подготовки или
после первого ввода ключа. Если работать программа не может (экран «Не
найден компонент обработки видео» и другие экраны поломки, §10), видео не
открывается.

Программа работает в одной копии: если окно уже открыто, повторный запуск
второго окна не создаёт, а передаёт путь открытой копии и выводит её окно
вперёд (`windows/runner/main.cpp`; если окно первой копии не нашлось за
5 с, открывается вторая копия). Видео от повторного запуска
(`receiveFromAnotherLaunch` в `app_controller.dart`):
- программа свободна — главный экран, «Обработка остановлена» или экран
  ошибки, и ничего не идёт — видео открывается сразу, как при
  перетаскивании в окно; нет готовой сессии — начинается платная
  обработка;
- программа ещё не готова — запускается или ждёт первого ввода ключа (и
  после «Удалить ключ») — видео ждёт и откроется на главном экране сразу
  после ввода ключа;
- это же видео уже открыто — идёт его обработка, сохранение или смена
  языка, на экране его предпросмотр или ключ меняют с экрана этого видео,
  — ничего не происходит, только запись в журнал «Это видео уже открыто»;
- ключ меняют с главного экрана — сообщение «Сначала закончите со сменой
  ключа» с подсказкой нажать «Проверить и сохранить» или «Отмена» и
  перетащить видео ещё раз;
- во всех остальных случаях — идёт обработка, сохранение или смена языка
  другого видео, на экране предпросмотр другого видео, ключ меняют с
  экрана другого видео, программа ещё проверяет другой выбранный файл, —
  сообщение «Сначала закончите с текущим видео» с подсказкой вернуться на
  главный экран и перетащить видео ещё раз. В очередь такое видео не
  встаёт: открывшись само позже, посреди правки чужого ролика, оно бы
  запутало, а его распознавание оплатилось бы без спроса;
- экран поломки («Не найден компонент обработки видео» и подобные) —
  видео не открывается, только запись в журнал.

Папка видео в журнал не попадает и здесь: она скрыта с первой же записи о
видео (§11).

**Длинный ролик.** Больше 15 минут: мягкое предупреждение («Длинный ролик.
«<имя>» длится N мин — дольше 15 минут. Обработка займёт много времени и
обойдётся дороже. Продолжить?») с кнопками «Продолжить» и «Отмена». Это не
жёсткий стоп — следователь решает сам. Для видео, у которого уже есть готовая
сессия (§9), вопрос не задаётся: оно открывается без запросов.

**Язык определяется сам, вопросов нет.** Обработка стартует сразу после
выбора файла. Если для видео уже есть сессия с тем же отпечатком (§9), она
открывается как есть — без проб, без оплаты и без перезаписи: если в ней
всё распознано и переведено, сразу открывается предпросмотр, иначе обработка
продолжается с того же места.

Иначе после нарезки (§6) идут пробы: две самые длинные реплики из разных
частей ролика распознаются моделями всех языков из «Настройки → Языки ваших
записей» (по умолчанию турецкий и узбекский). Реплика, на которой хоть одна
модель получила ошибку сервиса, в сравнение не идёт.

Тексты оцениваются по словам, а не по буквам: модель пишет только своими
буквами и на чужой речи, так что буквы показывают, какая модель писала, а не
на каком языке говорили (`lexicon.dart`). Признаки: доля слов из словаря
своего языка, характерные окончания, «чужие» слова соседнего языка,
узнанные по скелету, относительная длина текста, штрафы за зацикливание и
однообразие. Обычные слова, лишь похожие по окончанию на соседний язык
(турецкие aman, kavga, yardımı), ничьи: очка за своё окончание или штрафа
за чужое они не дают ни одной модели. Веса и пороги — в
`language_detector.dart`; подобраны на выдуманных примерах и требуют
калибровки на настоящих выводах SpeechKit.

Итог — язык, второй по оценке язык и уверенность:
- `high` — отрыв ≥ 0,25, у лидера ≥ 12 слов и ≥ 30 % своих, ответили все
  модели и реплики «проголосовали» одинаково (реплика, на которой два
  лидера набрали поровну, не голосует); при единственном отмеченном
  языке выбирать не из чего — `high`, если модель хоть что-то услышала;
- `low` — выбран лучший, но условия `high` не выполнены;
- `none` — все модели промолчали (пустые ответы): берётся язык прошлой
  обработки, без него — первый из настроек.

Если уверенность ниже `high`, ещё две реплики распознаются только двумя
лидерами, и решают они. Обработка идёт дальше в любом случае. При `low` и
`none` предпросмотр показывает жёлтую плашку: «Скорее всего <язык>. Если
перевод выглядит бессмысленным — [Распознать как <второй>]» (при `none`:
«Язык по речи определить не удалось — выбран <язык>…»).

До обработки язык не выбирается. Задать его заранее можно, оставив в
настройках один отмеченный язык; после обработки — меню «Не тот язык?».
Спрашивает о языке только отладочный стенд разработчика.

Вырожденные случаи: найден один сегмент — пробуется он один; сегментов нет —
ошибка «Речь в ролике не обнаружена» (§10).

Пробные распознавания не пропадают: тексты всех языков сохраняются в сессию
(`probeTexts`), реплики выигравшего языка повторно не отправляются, а при
смене языка не оплачиваются реплики, у которых есть пробы нового языка. Если
сервис не ответил — две пробы подряд остались без ответа или ни одна проба
первого этапа не получила текста из-за временной ошибки, — язык наугад не
выбирается и сессия не пишется: «Нет доступа к интернету» или «Сервис
Яндекса временно недоступен» с кнопкой «Повторить». Нарезка тогда
удаляется сразу (§11), а пробы, успевшие получить ответ, не сохраняются:
«Повторить» начинает с подготовки звука, и пробы оплачиваются снова.

**Отмена обработки**: кнопка «Отмена» есть на всех шагах. Текущий запрос к
Яндексу дожидается ответа (сервис мог его уже выполнить, и за него
заплачено), новых запросов нет, пауза перед повтором обрывается сразу.
Текущая команда ffmpeg дорабатывает, новые не запускаются: поиск пауз и
нарезка проверяют отмену перед каждым проходом и каждым сегментом. На экране
— «Останавливаем…» с пояснением. Дальше:
- отмена при подготовке звука или определении языка нового видео —
  «Обработка остановлена. Распознать ничего не успели.» и «На главный экран».
  Пробы не сохраняются, сессии нет, нарезка удаляется сразу (§11);
- отмена при распознавании или переводе — «Уже распознанное сохранено: если
  открыть это видео снова, обработка продолжится с того же места.» и выбор:
  «Открыть, что успели» или «На главный экран». В предпросмотре
  нераспознанные реплики — серые «ещё не распознано», сверху плашка
  «Обработка была остановлена: распознано N из M реплик» с кнопкой
  «Продолжить распознавание»; уже распознанное повторно не оплачивается;
- отмена, пока заново режется ролик уже начатой сессии (нарезка пропала),
  — как при распознавании, если в сессии что-то распознано;
- отмена платной смены языка отменяет её целиком (ниже).

Закрытие окна посреди работы тоже отменяет обработку. Запущенные ffmpeg
программа останавливает по их PID и ждёт, пока сохранение удалит временный
`<имя>_ru.partial.mp4`, а подготовка звука — `audio.wav`, но не дольше 5 с.

**Смена языка после обработки**: в шапке предпросмотра — «Язык: <язык> ·
Не тот язык?». В меню сначала второй по оценке язык, затем языки из
настроек и языки, на которых ролик уже распознан или начат, затем «Другой
язык…» — диалог со всеми языками распознавания (их 16). Пометка у языка
зависит от его резервной копии (§9):
- «готово — переключить»: на этом языке всё распознано и переведено —
  переключение бесплатное и мгновенное, вместе с правками;
- «распознано — осталось перевести, оплачивается только перевод»: все
  реплики распознаны, перевод не закончен (например, «Отмену» нажали на
  последнем запросе распознавания) — при выборе ролик только переводится;
- «начато — доделать, оплачивается только оставшееся»: распознана часть
  реплик — распознаются остальные, уже распознанные повторно не
  оплачиваются;
- «распознать заново — оплачивается»: копии нет или в ней ничего не
  распознано — обработка «Готовим звук → Распознаём речь → Переводим на
  русский», без определения языка. Не оплачиваются реплики, у которых есть
  пробы этого языка.

В «Другой язык…» те же состояния помечены коротко: «готово», «распознано»,
«начато». Жёлтая плашка сомнения пишет рядом с кнопкой «Распознать как
<второй>»: «уже готово — бесплатно», «уже распознано — оплачивается только
перевод», «уже начато — оплачивается только оставшееся» или «оплачивается».
Доделывание «начатого» и «распознанного» идёт той же обработкой, что и
платная смена.

При любой смене текущий вариант с правками уходит в резервную копию своего
языка, и к нему можно вернуться через это же меню. Если в текущем варианте
есть ручные правки — сделанные сейчас или при прошлом открытии видео (в
сессии они помечены `edited`, §9), — меню предупреждает: «Ваши правки
останутся в варианте «<язык>» — к нему можно вернуться через это же меню».
Отдельного подтверждения нет. После смены язык считается выбранным
человеком: уверенность `null` (плашки сомнения нет), вторым языком
становится прежний.

«Отмена» платной смены возвращает прежний вариант целиком: основной сессией
снова становится прежний язык с правками, а то, что успели распознать на
новом, уходит в резервную копию нового языка (сообщение «Смена языка
отменена»); в меню этот язык тогда подписан «начато» или «распознано».
Нарезка к моменту смены обычно уже удалена (§11), поэтому
платная смена языка режет ролик заново — это минуты работы ffmpeg, а не
деньги.

## 6. Пайплайн обработки

Портируется с проверенного вручную прогона (2026-09-02, три реальных ролика);
числа сегментации — оттуда.

1. **Аудио**: `ffmpeg -i video -vn -ac 1 -ar 48000 -c:a pcm_s16le audio.wav`.
   Звук нужен только для поиска пауз и нарезки и удаляется сразу после
   неё, удачной или нет (на час видео это около 345 МБ).
2. **Паузы, адаптивный порог**: `silencedetect` последовательно на
   −30 dB/0.3 с → −25/0.3 → −20/0.25 → −18/0.25 → −15/0.25, пока не найдётся
   ≥ 1 паузы на 15 с длительности (шумные ролики со стройплощадок не имеют пауз
   на −30 dB — проверено). Найденный порог пишется в сессию.
   **Терминальный фолбэк**: если пауз не нашлось ни на одном пороге, ролик
   режется принудительно по 7.2 с без опоры на паузы; в сессии ставится флаг
   `forcedSplit`, а в предпросмотре — одна плашка на весь ролик: «В записи не
   нашлось пауз, поэтому ролик разрезан на равные куски: фраза может
   оборваться на границе реплик и продолжиться в следующей».
3. **Сегменты**: речевые интервалы между паузами; склейка соседних, если зазор
   ≤ 1.0 с и суммарно ≤ 8 с; интервалы > 8.5 с делятся по микропаузам
   (порог +3 dB, d = 0.15 с), в крайнем случае принудительно по ~7.2 с;
   паддинг в тишину — `min(0.12 с, зазор_до_соседа / 2)` с каждой стороны,
   чтобы соседние сегменты **никогда не перекрывались** (иначе один и тот же
   звук ушёл бы в платный API дважды и дал бы наложение реплик в SRT);
   точность границ 0.01 с. Целевая длина 2–8 с (лимит STT v1 — 30 с / 1 МБ).
   **Ноль сегментов** (звук есть, речи нет): обработка останавливается с
   ошибкой «Речь в ролике не обнаружена» и кнопкой «На главный экран».
   Ручного ввода реплик в v1 нет.
4. **Кодирование**: каждый сегмент → OggOpus 64k mono (`-c:a libopus -b:a 64k`).
5. **Распознавание**: POST
   `stt.api.cloud.yandex.net/speech/v1/stt:recognize?topic=general&format=oggopus&lang=<код>`,
   заголовок `Authorization: Api-Key …`, тело — ogg.
   `format=oggopus` передаётся **явно** (в ручном прогоне он же и является
   значением по умолчанию, но полагаться на умолчание API не нужно);
   `sampleRateHertz` для OggOpus не передаётся. `folderId` **не передаётся** —
   доки прямо запрещают его для ключа сервисного аккаунта: каталог берётся из
   самого аккаунта. Язык всегда явный, полные коды `tr-TR`/`uz-UZ`; узбекский
   возвращается латиницей — показываем как есть.
   Реплики распознаются по одной, последовательно; после каждой сессия
   записывается на диск. Параллельные запросы (квота API — 20 в секунду) —
   возможное ускорение, не сделано.
6. **Перевод**: машинный (нейросетевой переводчик Яндекса, Translate API v2 —
   не языковая модель: он дешевле, детерминирован и не требует промптов).
   Непустые реплики уходят батчами в `translate/v2/translate`,
   `folderId` так же не передаётся (то же правило сервисного аккаунта).
   Коды языков здесь — **короткие**: `targetLanguageCode: "ru"`,
   `sourceLanguageCode` — `"tr"` или `"uz"`, полученные преобразованием кода
   распознавания (`tr-TR` → `tr`, `uz-UZ` → `uz`). Передача полного кода
   локали в Translate — ошибка запроса. Лимит 10 000 знаков на запрос
   считается по **сумме** всех строк батча; квота — 20 запросов в секунду
   и 1 млн знаков в час (нам с батчами до неё далеко).
   Перевод — один вызов на все реплики, которые его ждут (внутри — батчи),
   и автоповторы повторяют вызов целиком. Сессия записывается после
   перевода: если хоть один батч не получен и после повторов, не
   сохраняется весь перевод. Реплики, перевод которых стёр человек
   (`edited`, §9), заново не переводятся.

   **Про узбекский отдельно.** В переводчике это два разных языка: `uz` —
   латиница, `uzbcyr` — кириллица. Мы отправляем `uz`, потому что
   распознавание узбекского в SpeechKit возвращает именно латиницу (так
   написано в документации и так вышло на живом прогоне). Оригинал в
   программе не правится, поэтому кириллица туда не попадает; `uzbcyr`
   понадобится, только если появится правка оригинала с повторным переводом —
   определять его тогда по фактическому алфавиту текста, а не по языку
   ролика.
7. **Итог этапа**: список реплик → предпросмотр (§7).

**Статус каждой реплики** (поле в модели и в файле сессии) — от него зависит,
что будет отправлено в платный API при возобновлении:

| Статус | Значение | При возобновлении |
|---|---|---|
| `pending` | ещё не распознавалась — в том числе после отмены, остановки по ключу (401/403) или по отсутствию сети | отправляется |
| `ok` | распознан непустой текст (или человек вписал текст в `empty`) | не отправляется |
| `empty` | распознано, речи нет (шум техники) | не отправляется |
| `failed` | запрос не удался: повторы исчерпаны (429/5xx/нет ответа) или сервис вернул другую ошибку | отправляется |

Реплика со статусом `empty` не попадает в субтитры, но остаётся в списке серой
строкой «речи нет»: человек видит, что участок не потерян, а осознанно пуст,
и может вписать текст руками — тогда реплика становится `ok` и попадёт в
видео.

**Политика ошибок сети — одна и та же для распознавания и перевода**:
429/5xx/нет ответа — попытка и до трёх повторов с паузами 1 с, 4 с и 10 с
(итого не больше четырёх обращений и 15 с ожидания на реплику); после
исчерпания реплика получает статус `failed`, **остальной ролик обрабатывается
дальше** и доходит до предпросмотра (терять уже оплаченные соседние сегменты
нельзя). Другие коды ошибок не повторяются: реплика сразу `failed`.
401/403 — немедленная остановка всего прогона с сообщением про ключ или
роль; распознанное к этому моменту записано.

**Нет сети.** Если без ответа (ни кода, ни тела) остались две реплики подряд
со всеми повторами или сервис не ответил ни разу, ждать дальше бессмысленно:
обработка останавливается с «Нет доступа к интернету», уже распознанное
записано, «Повторить» продолжит с того же места. Перевод без ответа —
так же: распознанное сохранено, «Повторить» доделает перевод. Перевод, не
полученный из-за 429/5xx, помечает реплики «перевод не получен», и
обработка доходит до предпросмотра. Таймауты запроса: соединение 15 с,
отправка и приём по 60 с.

Стоимость (ориентир, тарифы РФ на сентябрь 2026, в приложение не зашивать):
STT тарифицируется на каждый запрос блоками по 15 с с округлением ВВЕРХ
(0.1626 ₽ за блок), перевод — 500.4 ₽ за 1 млн знаков; ролик на 90 с обходится
примерно в 3 ₽. Следствие для сегментации: без необходимости не плодить
сегменты короче ~2 с — каждый всё равно оплачивается как 15 с.

**Прогресс** — список шагов с галочками, текущий выделен:
- «Готовим звук» с подсказкой «Делим запись на фразы — на длинном ролике
  это может занять несколько минут.» Доли у шага нет: ядро её не сообщает.
  Проходов `silencedetect` до шести (пять порогов и проход по микропаузам),
  затем по запуску ffmpeg на каждый сегмент;
- «Определяем язык» — с полосой по числу пробных запросов;
- «Распознаём речь: 4 из 13» — счёт от всех реплик ролика;
- «Переводим на русский».

Язык показывается под именем файла, как только определён. Сохранение видео
(§8) показывает «Сохраняем видео с субтитрами… 47 %», затем «Проверяем,
что субтитры видны в кадре…».

## 7. Предпросмотр и правка

- **Раскладка**: в окне шире 900 точек плеер слева, список реплик справа;
  уже — плеер сверху. В окне ниже 480 точек экран не сжимается, а
  прокручивается целиком.
- **Плеер**: на Windows — media_kit (libmpv со своим ffmpeg и ANGLE рядом с
  exe, программное декодирование, только локальные файлы), на Android и
  macOS — video_player. Файл открывается на паузе в начале. Щелчок по кадру
  — пауза или воспроизведение, под кадром кнопка, время и ползунок. Не
  открылся — вместо кадра «Не удалось показать видео — субтитры можно
  проверить и сохранить»: предпросмотр — удобство, а не условие.
- **Субтитры в кадре** рисует **сам Flutter** поверх кадра — тем же шрифтом
  (NotoSans) и стилем, что вшивает libass: белый, чёрная обводка, низ по
  центру, размеры от высоты кадра. Правило, какие реплики и с каким текстом
  попадают в кадр, общее со вшиванием (`subtitleText`): в кадре ровно то,
  что окажется в видео. Правка текста видна в кадре мгновенно, без пересборки
  SRT. Предпросмотр приблизителен: итоговый кадр рисует libass, и совпадение
  с ним не пиксельное.
- **Список реплик**: время начала, оригинал серым (не правится), перевод в
  поле правки. Правка на диск (сессия и оба .srt) уходит через 0,7 с после
  последнего нажатия. Щелчок по строке — перемотка на начало реплики; при
  воспроизведении список сам прокручивается к звучащей реплике, но не пока
  человек печатает.
- **Чего нет**: время не правится; удаления, склейки, добавления и
  разделения реплик нет. Валидации таймингов в интерфейсе нет:
  `validateTimings` в ядре есть, но не вызывается — время не редактируется.
- **Серые строки**: `empty` — «речи нет» (вписанный текст делает реплику
  `ok`, и она попадёт в видео), `pending` — «ещё не распознано».
- **Подсветка «проверить»** (наследник ручной пометки `[ПРОВЕРИТЬ]`) —
  жёлтые строки с причиной под текстом:
  - «возможен сбой распознавания — повтор слова» — одно слово подряд
    четыре раза и больше;
  - «не распознано — впишите сами» — статус `failed`;
  - «перевод не получен» — оригинал есть, перевода нет.
  Принудительная нарезка строки не красит: о ней одна плашка над списком.
  Жёлтая строка не мешает сохранить — это подсказка, решает человек.
- **Шапка**: «Реплик N · проверить M» и кнопка «Следующая на проверку»;
  «Язык: <язык> · Не тот язык?» (§5). Под шапкой — плашки: сомнение в языке,
  «Обработка была остановлена…», принудительная нарезка, файлы в папке
  программы (§9, с кнопкой «Открыть папку»).
- **Внизу**: «Сохранить видео с субтитрами» и «Другое видео». Пока идёт
  сохранение или смена языка, правка закрыта. После сохранения — зелёная
  плашка «Готово: <имя>_ru.mp4» с папкой и кнопками «Открыть папку»
  (Android — «Поделиться»), «Посмотреть результат» и «Другое видео».
  «Посмотреть результат» открывает готовый файл в том же плеере — без
  второго слоя субтитров, со списком, закрытым для правки, и кнопкой
  «Вернуться к правке». Правка после сохранения снимает «Готово»: видео
  надо сохранить заново.

## 8. Вшивание

- **Порядок сохранения**:
  1. Дописываются свежие правки; оба .srt переписываются рядом с видео
     (они лежат там с конца обработки и обновляются после каждой правки).
  2. Нет ни одной реплики с переводом — «Нет ни одной реплики с переводом»,
     кодирования нет.
  3. Для ffmpeg отдельно пишется `burn_ru.srt` в рабочую папку видео (§11) —
     с обезвреженной разметкой (ниже). После вшивания, удачного или нет, он
     удаляется.
  4. До кодирования проверяется, можно ли заменить `<имя>_ru.mp4`: файл
     занят другой программой — сразу «Файл … открыт в другой программе…»,
     без кодирования; нет прав на запись — видео пойдёт в запасную папку (§9).
  5. ffmpeg пишет во временный `<имя>_ru.partial.mp4` рядом с целью. Если
     ffmpeg не пустили писать рядом с исходником, а программу пустили
     («Контролируемый доступ к папкам» разрешается каждому exe отдельно),
     кодирование повторяется в запасную папку.
  6. Автопроверка видимости субтитров (ниже). Провал — временный файл
     удаляется, прежний `<имя>_ru.mp4` не трогается.
  7. Прежний `<имя>_ru.mp4` удаляется, временный получает его имя. Если
     замена не удалась — прежний файл занят (открыт в плеере) или любой
     другой сбой, — сохранение заканчивается ошибкой, а проверенное видео
     ждёт под временным именем рядом с целью: «Повторить» только ставит
     его на место, без нового кодирования, если файл не менялся и правок
     с тех пор не было. При правке, смене языка, другом видео или
     закрытии окна оно удаляется.
- Windows:
  `ffmpeg -y -hide_banner -loglevel error -i <видео> -vf "subtitles='<рабочая папка>/burn_ru.srt':fontsdir='<папка приложения>/fonts':force_style='FontName=Noto Sans,Outline=2'" -c:v libx264 -crf 18 -preset veryfast -c:a copy -movflags +faststart -progress pipe:1 <имя>_ru.partial.mp4`
  Кодек и качество заданы явно. Аудио копируется без перекодирования.
  Шрифт NotoSans-Regular.ttf при каждом запуске распаковывается из ассетов
  в папку приложения (на Windows — `%APPDATA%\ru.subtitler\subtitler\fonts`)
  и берётся оттуда, чтобы не зависеть от набора шрифтов служебного ПК
  (libass на Windows ищет шрифты через DirectWrite). Копию `fonts/` рядом с
  exe CI кладёт в ZIP, но программа её не читает.
- Android: та же команда через ffmpeg_kit_flutter_new, плюс обязательная
  подготовка шрифта: NotoSans-Regular.ttf копируется из ассетов в папку
  приложения и регистрируется через `FFmpegKitConfig.setFontDirectoryList()`,
  а в фильтре дублируется `fontsdir=`. `FontName` — внутреннее имя семейства
  («Noto Sans»), не имя файла.
- **Автопроверка видимости субтитров** (критично: на Android без регистрации
  fontconfig libass «успешно» вшивает невидимый текст с кодом возврата 0).
  Метрика конкретная, устойчивая к шуму компрессии, яркости фона и сдвигу
  кадров: момент проверки — середина реплики с самым длинным переводом;
  из готового видео берётся кадр в этот момент, из исходного — все кадры
  окна ±0,1 с (ffmpeg пишет их нижние полосы во временную папку системы —
  на Windows `%TEMP%\band_*`, — и она удаляется сразу после чтения); в
  нижней полосе кадра (нижние 20 % высоты) для каждого кадра
  окна считается число пикселей, чья яркость отличается от готового кадра
  больше чем на 64 в любую сторону, и берётся наименьшее. Вшивание
  считается успешным, если таких пикселей не меньше max(12, 0,05 % площади
  полосы). Иначе — ошибка «Субтитры не отрисовались» (§10), видео под
  готовым именем не появляется.
  Как пришли к этой метрике (замеры 2026-09-25 на синтетике и публичных
  реальных роликах, 480x270…1280x720, вертикальных и повёрнутых):
  - первая версия считала прирост «почти белых» пикселей (яркость > 200) и
    ошибалась на реальных роликах: на светлом низу кадра белый текст ничего
    не добавляет, а чёрная обводка гасит светлое, и прирост уходит в минус;
    реплика в одно слово не набирала порога и на тёмном;
  - сравнение «кадр с кадром» ловит соседние кадры: кодировщик округляет
    начало видео до кадра, у телефонов плавает частота — на движущейся
    картинке без субтитров находились тысячи изменённых пикселей. Отсюда
    окно и минимум по нему; попиксельное «отличается от всех кадров окна»
    на движущемся фоне теряло видимые субтитры;
  - шум перекодирования с `-crf 18` порог 64 не переходит: без субтитров
    изменённых пикселей 0–3 на любом ролике. «А?» на кадре 320x240 даёт
    около 28, отсюда нижний предел 12, а не 40.
  - в MPEG-TS с редкими ключевыми кадрами быстрая перемотка не выдаёт
    кадра — тогда кадр берётся точной перемоткой (`-ss` после `-i`).
- Прогресс кодирования: на Windows — парсинг `-progress pipe:1` из stdout
  процесса; на Android — нативный statistics-callback ffmpeg_kit (у библиотеки
  нет доступного из Dart stdout). Это два разных механизма за одним интерфейсом
  `FfmpegRunner`.
- **Пути в `-vf`** собираются хелпером: обратные слэши заменяются прямыми,
  экранируются `:` и `'`, сами пути — в одинарных кавычках (без них
  двоеточие диска разбирается как начало следующей опции фильтра).
- **Текст в `burn_ru.srt`** обезврежен: `<`, `{`, `}` и `\` ffmpeg и libass
  приняли бы за разметку, и текст пропал бы из кадра. Скобки
  экранируются (`\{`, `\}`), а после `<`, `\{` и каждого `\` ставится
  невидимый U+2060 — libass его не рисует. Файлы .srt рядом с видео — для
  человека и других плееров: в них текст как есть. Во всех SRT строки
  реплики без пробелов по краям, пустые строки внутри реплики убраны.
- **Имена и коллизии**: `<имя>_ru.mp4`, `<имя>_orig.srt`, `<имя>_ru.srt` и
  временный `<имя>_ru.partial.mp4`, где `<имя>` — имя видео без расширения.
  Файлы принадлежат этому видео и этой сессии, поэтому перезаписываются без
  вопросов; исключение — если файл занят другим приложением: тогда сообщение
  «Файл <имя> открыт в другой программе, закройте его и повторите».
- **Выдача на Android**: кнопка «Поделиться» отправляет одним интентом три
  файла — mp4 и оба .srt (share_plus). В галерею видео не сохраняется:
  пакет gal в pubspec есть, но не используется.

## 9. Сессия

Рядом с исходником — `<имя видео с расширением>.subtitler.json` (для
`clip.mp4` — `clip.mp4.subtitler.json`). Схема 2:

- `schemaVersion`, `videoPath`, `fingerprint` {`sizeBytes`, `durationSec`};
- `lang`, `langConfidence` (`high` | `low` | `none`; `null` — язык выбрал
  человек или сессия записана по схеме 1), `langRunnerUp`;
- `probeTexts` — пробы всех языков: язык → номер реплики (строкой) → текст;
- `silenceThreshold`, `forcedSplit`;
- `cues[]` — {`index`, `range` {`start`, `end`}, `orig`, `ru`, `status`,
  `flags` [`repeatLoop` | `translateFailed` | `forcedSplit`], `edited`}.

Поле `edited` — перевод правил человек. Оно необязательное и пишется только
со значением `true`, поэтому схема из-за него не поднималась: прежние версии
такую сессию прочитают. Стёртый человеком перевод — его решение: заново он
не переводится, и сессия с ним считается готовой. Сессии схемы 1 читаются
(уверенность `null`, проб нет). Схему новее нашей программа не угадывает:
такой файл для неё нечитаемый (ниже).

- **Отпечаток исходника** (размер в байтах + длительность до 0.01 с) пишется в
  сессию и сверяется при открытии. Не совпал — сессия считается чужой и
  игнорируется, пайплайн запускается заново. Без этой проверки другой файл с тем
  же именем (обычное дело при работе с копиями вещдоков) молча получил бы чужие
  реплики. Путь в отпечаток не входит: сессия подходит и видео, которое
  перенесли вместе с ней (скопировали папку дела, флешка получила другую
  букву). Открытая сессия привязывается к пути, по которому видео открыли, и
  правки, .srt и резервные копии пишутся к нему, а не к пути внутри JSON.
  Найденную сессию определение языка не перезаписывает.
- **Когда пишется**: после определения языка (с пробами), после каждой
  распознанной реплики, после перевода (одним куском, §6) и в конце
  обработки; правки — через 0,7 с после последнего нажатия, а также перед
  сменой видео и закрытием окна. Обрыв сети или падение на последней минуте
  длинного ролика не обнуляют уже оплаченные вызовы.
- **Атомарная запись**: данные пишутся во временный `<файл>.tmp` рядом и
  встают на место переименованием — закрытие окна посреди записи не
  оставляет пустую сессию. Если переименование не удалось (файл «только для
  чтения» или его держит другая программа), запись уходит в запасную папку.
- **Нечитаемый файл** — обрезанный (в том числе посреди буквы),
  испорченный или записанный более новой версией программы — не
  затирается: при первой записи он откладывается под именем
  `<имя>.subtitler.broken-<ГГГГММДД-ччммсс>.json`, в журнал пишется
  предупреждение (вид ошибки и позиция, без содержимого файла), работа идёт
  с новой сессией.
- **Резервные копии по языкам** — `<имя видео с расширением>.subtitler.<код>.json`
  (например `clip.mp4.subtitler.uz-UZ.json`). Туда уходит вариант при смене
  языка (§5). «Готово» в меню «Не тот язык?» получают только копии, где всё
  распознано и переведено. Недоделанная копия подписана «распознано» (всё
  распознано, осталось перевести) или «начато» (распознана часть реплик) и
  при выборе доделывается платно — только оставшееся.
- **Папка только на чтение** (вещдоки на защищённом от записи носителе, сетевая
  шара, запрет от «Контролируемого доступа к папкам»): при неудаче записи
  рядом с исходником сессия и её копии уходят в папку приложения (на Windows
  — `%APPDATA%\ru.subtitler\subtitler`), а .srt и видео — в
  `%LOCALAPPDATA%\ru.subtitler\subtitler\output\<имя>_<хеш пути>\`.
  Предпросмотр показывает плашку «Рядом с видео записать нельзя — файлы
  сохранены в папку программы: <папка>» с кнопкой «Открыть папку» (на
  Android кнопки нет: файлы отдаются «Поделиться»). Если в запасную папку
  ушло только готовое видео, а .srt раньше записались рядом с исходником
  (например, ffmpeg не пустили писать рядом с исходником, §8), плашка так
  и говорит: видео — в папке программы, файлы .srt — рядом с исходным
  видео. Гарантия «без повторной оплаты» не должна молча ломаться из-за
  прав на папку.
  В запасной папке сессия называется `<имя видео>.<хеш пути>.subtitler.json`
  (копии — `….subtitler.<код>.json`): одноимённые вещдоки разных дел
  («VID_0001.mp4») не затирают друг друга. Файлы прежней версии без хеша
  читаются, но не пишутся.
  Своя сессия важнее чужого хеша. Сначала ищется своя: рядом с видео, в
  запасной папке под хешем текущего пути и под прежним именем без хеша;
  из подходящих по отпечатку берётся самая свежая по времени изменения
  файла (например, рядом с видео осталась старая, а правки ушли в запасную
  папку). Только если своей подходящей нет, читаются файлы с тем же именем
  видео (с учётом регистра букв) под чужим хешем — так сессия находится
  после смены пути: другой буквы диска, `\\server\share` вместо `Z:`. Из
  них тоже берётся самая свежая с совпавшим отпечатком. Так же ищутся
  резервные копии языков. Со своей сессией чужой хеш не спорит: иначе
  рабочая копия вещдока на диске открылась бы с текстом и правками
  оригинала, который открывали с защищённой флешки, а её первая же правка
  затёрла бы собственные.
- Ключ в сессию не пишется никогда.
- **Android**: видео — копия в кеше приложения (§3), и сессия, .srt и
  готовое видео пишутся рядом с ней, то есть тоже в кеш. Кеш система чистит
  при нехватке места — вместе с ним пропадут сессия с оплаченным
  распознаванием и результат. Запасная папка на Android — среди постоянных
  файлов приложения, но при записи в кеш она не нужна. Закрытое хранилище из
  §16a это исправит; к приложению оно ещё не подключено.

## 10. Ошибки

Принцип: каждая ошибка — человеческим языком + что сделать + кнопка по
смыслу. Карта (`describeError` в `lib/app/user_error.dart`):

| Ситуация | Сообщение | Кнопка |
|---|---|---|
| 401 | «Ключ неверный или отозван» — проверить ключ в настройках | «Изменить ключ» |
| 403 STT / 403 Translate | «У ключа нет роли ai.speechkit-stt.user» / «…ai.translate.user» — добавить роль в консоли облака | «Повторить» |
| 429 / 5xx на реплике | автоповтор молча; после трёх повторов реплика `failed`, обработка продолжается (§6) | — |
| 429 / 5xx на всех пробах языка | «Сервис Яндекса временно недоступен» | «Повторить» |
| Нет сети (§6) | «Нет доступа к интернету» — «Обработка возможна только онлайн…» | «Повторить» |
| Перетащили папку | «Это папка, а не видео» (сообщение, экран прежний) | — |
| Не видео или файл повреждён | «Это не видео или файл повреждён» (сообщение) | — |
| Файл без аудиодорожки | «В этом видео нет звука» (сообщение) | — |
| Речи не найдено (0 сегментов) | «Речь в ролике не обнаружена» | «На главный экран» |
| Пауз не найдено ни на одном пороге | не ошибка: ролик режется на равные куски, плашка в предпросмотре (§6) | — |
| Нечего вшивать | «Нет ни одной реплики с переводом» | — |
| Субтитры не отрисовались (провал автопроверки) | «Субтитры не отрисовались — сообщите разработчику»; в подсказке — где уже лежат .srt | — |
| Выходной файл занят | «Файл <имя> открыт в другой программе, закройте его и повторите» | «Повторить» |
| Нет места на диске | «Недостаточно места на диске для обработки» | «Повторить» |
| ffmpeg завершился с ошибкой | «Не удалось обработать видео» | «Повторить» |
| ffmpeg не запускается | «Не удалось запустить компонент обработки видео» | «Повторить» |
| Прочий сбой записи или чтения файла | «Не удалось записать или прочитать файл» | «Повторить» |
| Десктоп: нет ffmpeg или в нём нет libass | отдельный экран «Не найден компонент обработки видео» / «Компонент обработки видео неполный» — распаковать архив заново целиком | «Сохранить журнал» |

Где показывается: короткие сообщения («это не видео», «нет звука»,
«Сначала закончите с текущим видео», «Сначала закончите со сменой ключа»,
«Смена языка отменена», сбой бесплатной смены языка) — полосой над
экраном, этап не меняется; у них только текст и «Закрыть». Ошибки
обработки — отдельным экраном с кнопкой по смыслу и «На главный экран»;
ошибки сохранения — в полосе сохранения предпросмотра. На экранах ошибок
(и на экране поломки «Не найден компонент обработки видео») и в полосе
сохранения есть свёрнутые «Технические детали»: сырой текст ошибки и
последние 40 строк журнала (ключ и папки видео замаскированы, §11) с
кнопками «Скопировать» и «Сохранить журнал» (на экранах ошибок Android —
«Отправить журнал»). На экране ключа при неудачной проверке в «Технических
деталях» только сырой текст ошибки и «Скопировать».

Журнал работы (без ключа и без текста записей, §11) — боковая панель
«⋮ → Журнал работы» (или Ctrl+Shift+L); в настройках — «Открыть журнал»,
папка с журналом и «Сохранить журнал». Следователь может прислать его нам
при проблеме.

## 11. Безопасность и приватность

- Ключ: только в Credential Manager / Keystore; в UI маскирован; в журнал,
  сессии и краш-репорты не попадает (краш-репортов внешних нет вообще).
- Данные: аудиосегменты и тексты уходят **только** в API Яндекс Облака по HTTPS.
  Приложение ничего не отправляет никому другому (проверяемо: других доменов
  в коде нет, плеер предпросмотра открывает только локальные файлы).
  Допустимость передачи материалов в облако — на стороне регламента
  ведомства; README предупреждает об этом в самом начале.
- **Журнал**: его просят сохранить и отправить разработчику, поэтому
  материалов дела в нём нет. Текст реплик не пишется (только «пусто» или
  число слов); о нечитаемом файле сессии — только вид ошибки и позиция, без
  его содержимого. Папка видео заменяется на «…» во всех записях, в
  «Технических деталях» и в сохранённой копии — с первой же записи о видео,
  как бы его ни открыли: перетаскиванием, «Выбрать файл» или через значок
  программы; если вместо видео перетащили папку дела, скрывается и она.
  Имя файла видео остаётся.
  Скрыты именно папки с видео: пути профиля (папка программы, рабочая
  папка, файл журнала — в них имя учётной записи Windows) в журнале
  остаются. Ключ вырезается из любой записи. Хранятся два запуска:
  `subtitler.log` и `subtitler.prev.log`. На Windows журнал и его
  сохранённые копии («Сохранить журнал» — `subtitler-log-<время>.txt`,
  «Сохранить в файл» отладочного стенда — `subtitler-debug.log`) лежат в
  `%LOCALAPPDATA%\ru.subtitler\subtitler` — не в перемещаемом профиле,
  который уезжает на сервер профилей; на Android — в папке приложения.
  Журналы, которые прежние версии писали в Roaming (`subtitler.log`,
  `subtitler.prev.log`, `subtitler-debug.log` версий 0.1.x,
  `subtitler-log-*.txt` ранних сборок; в них был текст реплик и полные
  пути к видео), при запуске удаляются в фоне. Файл, который держит ещё
  открытая прежняя версия, удалится при следующем запуске. Других файлов
  в Roaming уборка не трогает.
- **Текст дела** хранится в файлах сессии (реплики и пробы всех языков) и в
  .srt — рядом с видео или в запасных папках (§9).
- **Временные файлы** — в рабочей папке видео
  `%LOCALAPPDATA%\ru.subtitler\subtitler\work\<имя>_<хеш пути>` (на Android —
  в кеше):
  - `audio.wav` удаляется сразу после нарезки, удачной или нет;
  - нарезка (`segments/seg_*.ogg`) удаляется, как только распознаны все
    реплики, а если определение языка нового видео не дошло до записи
    сессии (отмена на подготовке звука или определении языка, нет сети на
    пробах, любой другой сбой), — сразу: без сессии её никто не
    использует;
  - `burn_ru.srt` удаляется сразу после вшивания, удачного или нет;
  - нарезка недоделанной сессии остаётся, чтобы продолжить без повторной
    нарезки; рабочие папки, не менявшиеся дольше 7 дней, удаляются при
    запуске, как и рабочая папка прежних версий в Roaming.
- **Временное видео** `<имя>_ru.partial.mp4` лежит не в рабочей папке, а
  рядом с целью: рядом с исходником или в запасной папке `output` (§9).
  При сбое кодирования или проверки видимости оно удаляется сразу.
  Проверенное видео, которое не удалось поставить на место, ждёт
  «Повторить» и удаляется при правке, смене языка, другом видео или
  закрытии окна (§8).
- **Кадры проверки видимости** ffmpeg пишет во временную папку системы (на
  Windows `%TEMP%\band_*`); она удаляется сразу после чтения.

## 12. Технологии и зависимости

Версии подтверждены веб-исследованием 2026-09-10 (критичные выборы прошли
адверсариальную перепроверку по живым pub.dev/GitHub/докам) и сверены с
`pubspec.yaml` и `build.yml` 2026-09-25.

- **Flutter**: закреплён 3.44.6 (`FLUTTER_VERSION` в CI; в pubspec —
  `>=3.44.0`). Обновлять только как проверяемую миграцию, с ручным прогоном
  integration_test плеера (§14).
  Windows-тулчейн: только VS 2022 C++ (VS 2026 Flutter'ом не поддерживается).
  **Impeller**: в 3.44.6 Windows рисует через Skia. Impeller на Windows
  включён по умолчанию только с Flutter 3.47 (docs.flutter.dev/perf/impeller),
  а переключить рендерер в релизе 3.44 нечем: в `cpp_client_wrapper` SDK
  3.44.6 нет `set_impeller_switch`, релизная `flutter_windows.dll` не читает
  `FLUTTER_ENGINE_SWITCHES` (проверено по SDK). При переходе на 3.47 —
  прогон на старых GPU и по RDP и integration_test плеера: под Impeller
  текстура media_kit давала чёрный кадр. Отключение там —
  `project.set_impeller_switch(flutter::ImpellerSwitch::Disabled)` в
  `windows/runner/main.cpp`.
- **ffmpeg**:
  - Windows: статическая сборка gyan.dev **release-essentials 9.0.1**
    (`ffmpeg.exe` ~98 МБ): внутри всё нужное — silencedetect, libopus,
    libass (+freetype/fribidi/harfbuzz), libx264. ffprobe не везём:
    длительность читается из вывода ffmpeg. CI при каждой сборке качает
    архив прямо с GitHub (`GyanD/codexffmpeg`, релиз 9.0.1, `FFMPEG_URL` в
    `build.yml`) и проверяет в нём только фильтр `subtitles`. Зеркала в
    своём хранилище и сверки контрольной суммы пока нет — это ещё
    предстоит для воспроизводимости сборок.
  - Android: **ffmpeg_kit_flutter_new ^4.6.2** — живой форк закрытого в 2025
    FFmpegKit (релизы еженедельно, июль 2026); базовый пакет = full-gpl,
    FFmpeg 8.1.2, наличие libass/libx264 и фильтра `subtitles` проверено
    внутри самого Maven-артефакта. minSdk 24, 16KB-страницы поддержаны.
    APK собираем только arm64-v8a (~62 МБ; armeabi-v7a добавлять
    только если парк старых телефонов потребует — это ещё ~78 МБ).
    В pubspec версия задана как `^4.6.2` (в `pubspec.lock` — 4.6.2), а
    AAR `com.antonkarpenko:ffmpeg-kit-full-gpl:2.2.1` Gradle при сборке
    качает из Maven Central (`android/build.gradle` плагина). Точный пин и
    зеркало AAR в своём хранилище ещё не сделаны, хотя нужны: это форк
    одного мейнтейнера, а экосистема ffmpeg-kit уже дважды переживала смену
    рук. Плагин с v4.2.0 умеет и Windows, но на десктопе мы сознательно
    остаёмся на видимом `ffmpeg.exe`: пиновая, проверяемая ИТ-отделом
    сборка вместо скачиваемого на этапе билда бинаря. Свой ffmpeg плагин
    при сборке Windows всё равно кладёт рядом с exe (117 МБ) — CI его
    выбрасывает (§14).
    Лицензия итоговой сборки — GPLv3 (из-за libx264): для внутреннего
    использования обязательств нет; при передаче другим ведомствам —
    приложить LICENSE и ссылки на исходники.
- **Плеер предпросмотра**: общий интерфейс `PreviewPlayer`
  (`lib/ui/player/preview_player.dart`), на каждой платформе свой.
  - Windows: media_kit 1.2.6 + media_kit_video 2.0.1 +
    media_kit_libs_windows_video 1.0.11. libmpv со своим ffmpeg и ANGLE лежат
    рядом с exe и не зависят ни от Media Foundation, ни от кодеков ОС —
    работает и на N/LTSC-редакциях. Проект в режиме «limited maintenance»
    (объявлено 2025-11-25), но жив. Версии с pub.dev прибиты точно, git-пина
    нет. Плеер добавляет к папке ~46 МБ.
  - Android и macOS: video_player 2.14.0 (ExoPlayer / AVFoundation) — ни
    одной .so в APK не добавляет.
  - media_kit_libs_video и media_kit_libs_android_video подключать нельзя:
    они кладут в APK вторую копию ffmpeg (было 271 МБ вместо 60). CI падает,
    если в APK есть libmpv.so.
  - libmpv грузится по полному пути рядом с exe, а не через переменную
    окружения `LIBMPV_LIBRARY_PATH`.
- **Ключ**: flutter_secure_storage ^11.1.0. Windows: гибрид «.secure-файлы в
  app-support + ключ-обёртка в Credential Manager» (сборке нужен C++ ATL в VS
  Build Tools). Android: Keystore, minSdk 24. Исключить файл хранилища из
  Android Auto Backup (известный «Failed to unwrap key» после восстановления)
  ещё предстоит: правил бэкапа в манифесте нет.
  Любая ошибка чтения/расшифровки трактуется как «ключа нет» → снова экран
  ключа. Хранение per-user — плюс для общих служебных ПК.
- **Файлы**: share_plus ^13.3.0 — «Поделиться» на Android (видео и оба .srt
  одним интентом, журнал); desktop_drop ^0.8.4 — перетаскивание в окно
  (десктоп); file_selector ^1.1.0 — «Выбрать файл» (first-party).
  **В pubspec, но не используются**: receive_sharing_intent ^1.9.0 (приём
  «Поделиться» из WhatsApp), gal ^2.3.3 (галерея), window_manager ^0.5.2,
  wakelock_plus ^1.8.0 (телефон не засыпает при обработке). Их нативные
  библиотеки всё равно едут в сборку (`gal_plugin.dll`,
  `window_manager_plugin.dll` в ZIP).
- **Прочее**: dio ^5.11.1 — таймауты 15/60/60 с (`AppServices.newDio`),
  заголовок `Api-Key` в каждом запросе; интерсептора и `CancelToken` нет:
  отмена не прерывает запрос (§5). path_provider ^2.1.6, package_info_plus
  ^10.2.1. Состояние: ChangeNotifier/ValueNotifier, без фреймворков.
  UI по-русски: flutter_localizations с locale «ru» (иначе системные диалоги
  Material останутся английскими). Строки экранов оболочки, ключа, главного,
  обработки, настроек и журнала — в классе `AppStrings`
  (`lib/ui/strings.dart`); тексты предпросмотра (`lib/ui/review/`) и плеера —
  в самих виджетах; названия шагов, сообщения об ошибках и подписи их кнопок
  — рядом с логикой в `lib/app/`.
- **Шрифт**: NotoSans-Regular.ttf (кириллица + турецкие символы) в ассетах —
  один и тот же для предпросмотра и вшивания (§8).
- **Размер**: распакованная папка Windows ~178,5 МБ (ffmpeg.exe ~98, плеер
  ~46, Flutter, плагины и библиотеки MSVC ~34), ZIP ~69 МБ (замер сборки
  2026-09-25). CI падает, если папка больше 200 МБ.

## 13. Структура кода

```
lib/
  main.dart              // запуск: журнал сбоев, плееры, AppController + AppShell
  app/                   // состояние программы и связь с внешним миром
    app_controller.dart  // этапы, обработка, правки, смена языка, сохранение
    services.dart        // AppServices: диск, ffmpeg, сеть, хранилище — в тестах подделки
    runtime.dart         // папки программы, шрифт для libass, уборка рабочих папок и прежних журналов
    key_store.dart, key_check.dart   // хранилище ключа и его проверка
    output_files.dart    // имена выходных файлов, запасная папка, замена файла
    user_error.dart      // describeError: исключение → текст для человека (§10)
    settings.dart, video_probe.dart, launch_args.dart, reveal.dart, diagnostics.dart
    debug_controller.dart  // отладочный стенд
  core/                  // без Flutter
    models.dart          // Cue{index, range, orig, ru, status, flags, edited}, Session, отпечаток
    languages.dart       // 16 языков: коды распознавания и перевода
    session_store.dart   // сессии, резервные копии, запасная папка, атомарная запись
    srt.dart, cue_timeline.dart, logging.dart, path_hash.dart
    cloud/               // SpeechKitClient, TranslateClient, withRetry (общий для обоих)
    ffmpeg/              // FfmpegRunner (выполнить + прогресс) →
                         //   ProcessFfmpegRunner (десктоп, -progress pipe:1),
                         //   LibFfmpegRunner (Android, statistics-callback);
                         //   команды и экранирование — общие; поиск ffmpeg.exe
    pipeline/            // Pipeline; language_detector + lexicon + probe_cues;
                         //   silence_parser, silence_scanner, segmenter, segment_cutter;
                         //   burner (вшивание и проверка видимости); validation
    library/             // библиотека обработок Android (§16a) — к приложению не подключена
  ui/
    app_shell.dart       // оболочка: меню, журнал, перетаскивание, экран по этапу
    onboarding_view, home_view, processing_view, error_panel, settings_screen,
    log_panel, log_actions, strings
    player/              // PreviewPlayer: media_kit (Windows), video_player; оверлей субтитров
    review/              // предпросмотр: шапка, список реплик, плашки, полоса сохранения
    debug_screen.dart    // экран отладочного стенда
tool/pipeline_cli.dart   // прогон ядра из командной строки
```

Чистые функции без I/O: `silence_parser`, `segmenter`, `language_detector`,
`lexicon`, `probe_cues`, `validation`, `srt`, `cue_timeline`, `models`. Они
юнит-тестируются на синтетических данных. `core/` от Flutter не зависит;
платформенная специфика заперта в `core/ffmpeg/`, `app/services.dart`,
`app/runtime.dart`, `ui/player/` и в приёме/выдаче файлов.

## 14. Сборка и CI

- GitHub Actions (`.github/workflows/build.yml`) на пуш в `main`, на тег `v*`
  и вручную; Flutter 3.44.6:
  - **windows** (windows-2022, VS 2022): скачивает ffmpeg gyan.dev 9.0.1 и
    проверяет в нём фильтр `subtitles`; `flutter analyze` и `flutter test`
    с этим ffmpeg (тесты вшивания выполняются по-настоящему);
    `flutter build windows --release` → папка: содержимое `Release/` +
    `tools/ffmpeg/ffmpeg.exe` с LICENSE + `fonts/NotoSans-Regular.ttf` + рядом
    с exe ровно три DLL MSVC-рантайма (`msvcp140.dll`, `vcruntime140.dll`,
    `vcruntime140_1.dll` — официальный «application-local deployment»,
    работает без прав админа: UCRT входит в Windows 10/11). Свой ffmpeg
    плагина ffmpeg_kit (117 МБ) выбрасывается. Проверки: обязательные файлы
    на месте, DLL ffmpeg-kit не вернулись, папка не больше 200 МБ, каждая DLL,
    которую импортируют exe и DLL папки, лежит рядом или входит в саму
    Windows (dumpbin). Итог — `subtitler-windows-x64.zip`, артефакт на 14 дней;
  - **android** (ubuntu): ffmpeg из apt, analyze и тесты, `flutter build apk
    --release` (arm64-v8a, пока с отладочной подписью). Проверки: в APK есть
    разрешение INTERNET, архитектура одна, `libmpv.so` нет;
  - **release** — только по тегу `v*`: публикует Windows-ZIP в релиз GitHub
    с инструкцией запуска. APK в релиз не идёт, пока он не подписан своим
    keystore из секретов репозитория.
- **Перед тегом релиза — обязательно вручную**, на Windows:
  `flutter test integration_test -d windows` с заданной `SUBTITLER_FFMPEG`
  (без неё оба теста пропускаются молча, и зелёный итог ничего не значит).
  CI этот тест не запускает, а только он проверяет живой плеер: обновление
  Flutter или media_kit, из-за которого предпросмотр падает или показывает
  чёрный кадр, analyze, тесты, сборка и проверка DLL не заметят. Затем
  smoke-тест ZIP: распаковать, запустить `subtitler.exe`, открыть ролик,
  дойти до предпросмотра и увидеть кадр — лучше на чистой машине без
  VC++ Redistributable.
- Замечания для ИТ: скачанный из сети ZIP несёт Mark-of-the-Web →
  SmartScreen предупредит при первом запуске (раздавать через внутренний
  файлообменник или «Разблокировать» в свойствах файла); AppLocker/WDAC
  могут блокировать неподписанные exe и DLL из пользовательских папок — при
  жёсткой политике нужна подпись кода или white-list от ИТ-отдела. README
  внутри ZIP нет — это ещё предстоит. Сейчас подсказка про SmartScreen
  («Подробнее» → «Выполнить в любом случае») есть только на странице
  релиза (её текст — в `build.yml`), про AppLocker/WDAC — в разделе README
  «Для ИТ-службы»; про Mark-of-the-Web и «Разблокировать» нет ни в
  README, ни на странице релиза.
- Приёмочный прогон перед раздачей: реальные ролики на настоящей
  Windows-машине. Сами ролики и эталоны к ним в репозиторий не попадают
  (`test/acceptance/README.md`).

## 15. Тестирование

- Тестовые данные — только синтетические ролики и вымышленные фразы;
  настоящие записи и ответы сервисов в репозиторий не попадают.
- Юнит: парсер silencedetect, сегментация (склейка/деление/паддинг без
  перекрытий/терминальный фолбэк), SRT (сборка, экранирование для вшивания),
  эвристики подсветки, коды языков, определение языка (словари, оценка,
  выбор проб), модель и схемы сессии, хранилище сессий (запасная папка,
  атомарная запись, нечитаемые файлы), повторы и отмена, журнал.
- Клиенты API: фейковый HTTP-сервер (401/403/429/5xx, нет связи, тексты,
  батчи перевода).
- Конвейер и контроллер (`AppController`) — на подделках `AppServices` и с
  настоящим ffmpeg на синтетических роликах: возобновление без повторной
  оплаты, отмена на каждом шаге, отсутствие сети, смена языка, сохранение с
  проверкой видимости, запасная папка, занятый файл.
- Виджет-тесты: экран ключа, главный экран и оболочка, обработка и отмена,
  экраны ошибок, предпросмотр (список реплик, плашки, меню «Не тот язык?»,
  полоса сохранения, узкое и низкое окно), настройки, журнал, отладочный
  стенд. Плеер в них — подделка.
- Живой плеер (media_kit, ANGLE) — `integration_test/preview_player_test.dart`,
  только вручную (§14): libmpv и текстура работают лишь в собранном
  приложении.
- Тестам нужен ffmpeg: `SUBTITLER_FFMPEG` или ffmpeg в PATH. Без libass тесты
  вшивания пропускаются с объяснением причины.
- Приёмка: реальные ролики от «файл» до «_ru.mp4» (`tool/pipeline_cli.dart`),
  сверка с локальными эталонами; на Android дополнительно — тест
  автопроверки видимости субтитров (специально сломанная регистрация шрифта
  должна давать ошибку, а не «успех»).

## 16. Риски

| Риск | Смягчение |
|---|---|
| Форк ffmpeg-kit заброшен/сломан | прослойка FfmpegRunner: замена пакета не трогает остальной код; крайний вариант — свой AAR со сборкой ffmpeg |
| SpeechKit v1 объявят устаревшим | клиент изолирован в core/cloud; переход на v3 — замена одного класса |
| media_kit проблемен на Windows | субтитры уже рисуем сами; плеер за интерфейсом PreviewPlayer заменим (предпросмотр — не критический путь: без него субтитры проверяются и сохраняются) |
| Разъезжается Android-тулчейн (AGP 9.2 / Kotlin 2.4 / compileSdk 37 / minSdk 24 у разных плагинов) | первая задача плана реализации — скелет со ВСЕМИ зависимостями, собирающийся на обеих платформах, до любой фичи |
| Impeller на Windows (по умолчанию с Flutter 3.47) глючит на старых GPU/RDP или ломает текстуру плеера | Flutter закреплён на 3.44.6 (Skia); переход — прогон на целевом железе и integration_test плеера; отключение — `set_impeller_switch` в `windows/runner/main.cpp` |
| Определение языка ошибается на настоящих записях | пороги не откалиброваны (§5): неуверенный выбор виден плашкой, «Не тот язык?» доступно всегда, пробы повторно не оплачиваются |
| Android чистит кеш, где лежат видео, сессия и результат (§9) | закрытое хранилище из §16a |
| Антивирусы на служебных ПК | portable ZIP без самораспаковки; при жалобах — инструкция для ИТ-отдела |
| WhatsApp пережимает выданное видео | это норма мессенджера; оригинал остаётся у пользователя |

## 16a. Библиотека обработок на Android

Работа с галереей, хранение результатов и история обработок вынесены в
отдельный документ: [библиотека обработок](2026-09-11-android-library-design.md).
Коротко: видео из любого источника копируется в закрытое хранилище
приложения, в галерею и облачный бэкап не попадает, наружу отдаётся только
кнопкой «Поделиться». История ограничена местом на диске; при нехватке у
самых старых записей удаляются видео, текст сохраняется, и человек
предупреждается заранее. На Windows истории нет: там файлы лежат рядом с
исходником.

Сделано пока только хранилище (`lib/core/library/`, с тестами); приложение
его не использует.

## 17. Границы v1 → потом

v1: всё описанное выше. Потом (не сейчас): правка времени, удаление, склейка,
добавление и разделение реплик в редакторе, приём видео из WhatsApp через
«Поделиться», библиотека обработок на Android (§16a), параллельное
распознавание, пакетная обработка нескольких видео, авто-подбор громкости
для тихой речи (boost-ретрай из ручного прогона), транслитерация узбекской
латиницы в кириллицу, iOS.

Отдельно стоит держать в уме **глоссарий переводчика** (`glossaryConfig`):
Translate v2 позволяет приложить к запросу до 50 пар «термин → перевод»
(пары tr-ru и uz-ru поддерживаются). Для устойчивого перевода профессиональной
лексики и имён это самый дешёвый рычаг, но в v1 он не нужен: сначала надо
увидеть на реальных делах, какие термины переводятся не так.
